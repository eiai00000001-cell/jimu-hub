## 5. 指摘事項の詳細

### SEC-01 開発・テスト専用の環境変数が、配布版でも効いていた(要対応・是正済み)

- 該当箇所: `app/src/main/index.ts`、`app/src/main/ipc/data.ipc-handler.ts`
- 内容: 次の環境変数は、配布版(`.dmg` からインストールした `.app`)でも、起動時に設定されていれば効く状態でした。
  - `ELECTRON_RENDERER_URL`: 画面として読み込む URL を差し替えます
  - `JIMUHUB_DATA_DIR`: データの保存先を差し替えます
  - `JIMUHUB_E2E_EXPORT_PATH`・`JIMUHUB_E2E_IMPORT_PATH`: ダイアログを出さずに、指定したパスへ書き出す、または指定したパスから復元します
- リスク: 特に `ELECTRON_RENDERER_URL` は、外部のページを読み込ませると、そのページから preload の API を通じて取引先の全データ(氏名・住所・電話・メール)を読み出せます。ただし、悪用にはこのパソコン上で環境変数を指定してアプリを起動できる必要があります。そのため、実際に起こる可能性は低いと考えます。
- 実施した是正: 新しく `app/src/main/app-security.ts` を作り、補助関数 `readDevOnlyEnv()` を追加しました。この関数は、未パッケージ(開発・E2E テスト)のときだけ環境変数の値を返し、配布版(`app.isPackaged === true`)では無視します。上の4つの環境変数は、すべてこの関数を通して読むようにしました。E2E テストは未パッケージの状態で起動するため、テストの動作は変わりません。
- **動作への影響あり**。再テストの判断材料は6章にまとめました。

### SEC-02 画面遷移・新規ウィンドウ・権限要求の制限がなく、CSP も最小限だった(要対応・是正済み)

- 該当箇所: `app/src/main/index.ts`、`app/src/renderer/index.html`
- 内容: `will-navigate`・`setWindowOpenHandler`・`setPermissionRequestHandler` が設定されていませんでした。また、Content-Security-Policy に `object-src`・`base-uri`・`form-action` の指定がありませんでした。
- リスク: 本アプリには現在、外部へのリンクや画面遷移がありません。そのため直ちに害が出るものではありません。ただし、将来リンクを追加した場合や、取引先のメモ欄などを経由して想定外のスクリプトが動いた場合に、外部のページへ遷移して preload の API を使われるおそれがあります。これは Electron 公式のセキュリティチェックリストで推奨されている多層防御です。
- 実施した是正:
  - `applyWindowSecurity()` を追加しました。新規ウィンドウの作成をすべて拒否し、現在の画面以外への遷移を中止します。再読み込みは許可します
  - `denyAllPermissionRequests()` を追加しました。カメラ・マイク・通知などの権限要求をすべて拒否します
  - CSP に `object-src 'none'; base-uri 'none'; form-action 'none'` を追加しました
- **動作への影響あり**。再テストの判断材料は6章にまとめました。

### SEC-03 `.gitignore` に、SQLite の一時ファイルとエクスポートファイルの登録がなかった(参考・是正済み)

- 該当箇所: `.gitignore`
- 内容: `*.sqlite` は登録済みでしたが、書き込み途中に作られる `*.sqlite-wal`・`*.sqlite-shm` は登録されていませんでした。この2つにも取引先データが含まれます。また、アプリからエクスポートしたファイル(`事務HUB_backup_*.json`、個人情報を含む)も登録されていませんでした。
- リスク: 開発時にデータの保存先をリポジトリ内にした場合や、エクスポートファイルをリポジトリ内に保存した場合に、誤ってコミットされるおそれがあります。
- 実施した是正: 上の3つのパターンを `.gitignore` に追加しました。`git check-ignore` で、管理対象外になることを確認しています。動作への影響はありません。

### SEC-04 Electron Fuses が初期設定のまま(参考・未是正)

- 該当箇所: `app/electron-builder.yml`(配布版の `.app`)
- 内容: 生成した `.app` を調べたところ、`RunAsNode`・`EnableNodeOptionsEnvironmentVariable`・`EnableNodeCliInspectArguments` が有効でした。また、`EnableEmbeddedAsarIntegrityValidation`・`OnlyLoadAppFromAsar` は無効でした。
- リスク: 同じパソコン上で任意のコマンドを実行できる人は、アプリの実行ファイルを Node.js として動かしたり、アプリ内のファイルを書き換えたりできます。ただし、その状態ではすでにデータファイルを直接読めるため、新たに増えるリスクは小さいです。
- 是正案(担当: deployer または次イテレーションの developer): electron-builder の `electronFuses` 設定で上の項目を無効化・有効化することを提案します。Fuses を書き換えると、実行ファイルに付いている簡易署名(ad-hoc 署名)が無効になり、Apple シリコンの Mac では起動できなくなります。そのため、`identity: '-'`(ad-hoc 署名の再付与)などとあわせて変更し、実機で `.dmg` から起動できることの確認が必要です。影響が配布物全体に及ぶため、今回は変更していません。

### SEC-05 データベース・退避コピー・エクスポートファイルが暗号化されていない(参考・未是正)

- 該当箇所: `~/Library/Application Support/事務HUB/`(`data.sqlite` と、復元前の退避コピー `backups/`。直近3世代)、利用者が選んだ場所に保存されるエクスポートファイル(JSON)
- 確認結果:
  - データの保存先は macOS 標準のアプリ用フォルダで、その上の `~/Library` は所有者だけが開ける権限(700)になっています。ファイル自体は標準の権限(644)で作られますが、上のフォルダで他のユーザーからのアクセスは遮られます
  - 退避コピーは直近3世代だけが残り、それより古いものは自動で削除されます
  - エクスポートファイルの既定の保存先は「書類」フォルダ(こちらも所有者だけが開ける権限)ですが、利用者が別の場所を選ぶこともできます
- リスク: パソコンの紛失・盗難や、エクスポートファイルのうっかり共有(クラウド共有フォルダ、メール添付など)によって、取引先の個人情報が第三者に見られるおそれがあります。
- 対応: ご回答 Q3 に基づき、今回は暗号化しません。納品フェーズで deployer が作成する操作マニュアル.md に、次の事項の記載をお願いします。
  1. Mac のログインパスワードを設定し、FileVault(ディスクの暗号化)を有効にすること
  2. エクスポートファイルには取引先の個人情報がそのまま含まれるため、保存先に注意すること(共有フォルダ・クラウドの共有設定・メール添付を避け、外部ストレージは施錠できる場所で保管し、不要になったものは削除する)
  3. 復元前の退避コピーが、データの保存フォルダ内に最大3世代残ること
  4. パソコンを譲渡・廃棄するときは、データの保存フォルダとエクスポートファイルを削除すること(または macOS の初期化を行うこと)
- 今後の課題: バックアップ・エクスポートファイルの暗号化(パスワード付き)は、次イテレーション以降の機能追加の候補とします。

### SEC-06 未署名配布のため、利用者が配布物の改ざんを見分けられない(参考・未是正)

- 該当箇所: `app/electron-builder.yml`(`identity: null`、`hardenedRuntime: false`)
- 内容: 基本設計書の方針どおり、Apple Developer Program に登録せず未署名で配布します。そのため、配布の途中で `.dmg` が差し替えられても、利用者は気づけません。
- 是正案(担当: deployer): 納品書.md に、配布する `.dmg` の SHA-256 ハッシュ値(`shasum -a 256` の結果)を記載することを提案します。また、受け渡しは、依頼者ご本人と直接やりとりできる経路に限ることを提案します。

### SEC-07 不要な同梱物(参考・未是正)

- 該当箇所: 配布版の `app.asar`・`app.asar.unpacked`
- 内容: better-sqlite3 の Windows・Linux 用ネイティブバイナリ、SQLite の C ソース、drizzle-orm のソースマップが同梱されています。機微情報は含まれておらず、配布サイズが増えるだけです。
- 是正案(担当: 次イテレーションの developer): electron-builder の `files` に除外パターンを加えることを提案します。

## 7. 再発防止策(是正案)

導入・実装は、依頼元または developer の担当です。

1. **コミット前の自動検出**: pre-commit フックで gitleaks(または secretlint)を実行し、キー・トークンの形式を検出する。独自ルールとして、`/Users/<ユーザー名>/`・`/home/<ユーザー名>/`・`C:\Users\<ユーザー名>\` 形式の絶対パスや、`example.com` 以外のメールアドレスも検出する。
2. **画像の埋め込み情報の除去**: 証拠画像・モックアップ画像をコミットする前に、埋め込み情報を確認・除去する手順(例: `exiftool -all=`)を、テスト手順に加える。
3. **依存パッケージの定期確認**: `npm audit --omit=dev --audit-level=high` を、コミット前またはリリース前のチェックに組み込む。
4. **証拠画像の上書き防止**: E2E シナリオを実行し直すと、コミット済みの証拠画像が上書きされます。テスト実行時の出力先と、正式な証拠の保管先を分けることを提案します(担当: tester)。
5. **フェーズごとの呼び出し**: 各フェーズの成果物をコミットする前に、security-expert による簡易チェックを呼び出す運用を続ける。
