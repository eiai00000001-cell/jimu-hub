# プロジェクト概要

## 1. 文書情報

- 作成日: 2026-09-28
- 版数: v2.0
- 対象イテレーション: イテレーション1(見積書・請求書作成)

## 2. プロジェクトの目的・背景

「事務HUB」は、個人事業主である依頼者ご本人が日々行う事務作業を一つのツールに集約し、効率的に管理できるようにすることを目的として開発する。対象とする業務は、見積書・請求書の作成、入出金・経費の記録、取引先・案件の管理、タスク・期限の管理である。現時点でこれらの業務を管理している既存ツールは無く、今回新規に構築するものであり、既存システムからのデータ移行は発生しない。

## 3. 対象ユーザー・利用シーン

- 利用者: 依頼者ご本人のみ(唯一の利用者であり、複数ユーザーでの利用は想定しない)
- 利用端末: PCを中心とする
- 想定利用シーン: 見積書・請求書の作成、日々の入出金・経費の記録、取引先や案件情報の参照・更新、タスクや期限の管理など、個人事業の運営に伴う事務作業全般

## 4. 技術スタック・制約(初回確定分)

- 提供形態: インターネットには公開せず、ローカル環境のみで動作するデスクトップアプリケーションとする。
- 認証: 認証機能は設けない方針とする。PC自体のログイン・画面ロックによって保護することとする。ヒアリング当初は「ログイン必須」案も挙がったが、ローカル専用のデスクトップアプリであるという特性を踏まえ、「認証なし」に決定した。
- 具体的な使用言語・フレームワーク・データベース等の技術選定は、イテレーション0の設計フェーズ(基本設計書.md・詳細設計書.md)にて確定済みであり、イテレーション1以降はこれを前提として踏襲する。見積書・請求書のPDF出力機能など、新たに必要となる技術要素の選定は、次フェーズ(architecture)にて確定する。

## 5. セキュリティ・法令面の方針

- インボイス制度(適格請求書等保存方式)への対応: イテレーション総括.md(v1.0)で申し送られていた依頼者のインボイス登録状況(★7)について、イテレーション1のスコープ確認で「登録・未登録の両方に対応する」方針が確定した。設定画面にインボイス登録番号を入力した場合にのみ、見積書・請求書に適格請求書等保存方式の記載事項(登録番号等)を表示する。登録番号が未入力の場合は、区分記載請求書等の形式で出力する。
- 電子帳簿保存法への対応: ★8について、最小限の対応水準として「発行した見積書・請求書等の文書を改変せずに保存し、日付・金額・取引先の各条件で検索できるようにする」方針が確定した。詳細な保存形式・検索方式は設計フェーズで確定する。
- 見積書・請求書の出力形式: PDF保存のみとする(印刷は依頼者ご本人がPDFを開いて行う運用とし、アプリ側に印刷機能は設けない)。
- バックアップ: 手動エクスポート方式とし、エクスポートしたデータからの復元も可能な構成とする。起動エラー画面からの復元導線(★R1)は本イテレーションで追加する(6章参照)。
- 取引先の氏名・連絡先や金銭に関する情報に加え、見積書・請求書には依頼者ご自身の事業者情報(氏名・屋号、住所)や振込先口座情報も記載されるため、これらの取り扱いにも十分留意する。

## 6. 今回のイテレーションの位置づけと対象スコープの概要

イテレーション1は、イテレーション総括.md(v1.0)7章で優先度A(最優先)とされた「見積書・請求書の作成」機能を主対象とする。

主要機能として、次を含む。
- 見積書・請求書の作成・PDF保存(適格請求書等保存方式・区分記載請求書等の両対応、登録番号の入力有無で自動切替)
- 見積書から請求書への変換(ボタン一つで見積書の内容を引き継いだ請求書を作成)
- 請求書の入金ステータス管理(未収/入金済み。入出金・経費機能とは別管理とし、今回は請求書側のステータス項目として実装する)
- 自社情報・振込先の設定(氏名・屋号、住所、振込先口座など、書類に表示する事業者情報の設定画面)
- 源泉徴収税額の計算(個人事業主向け)

あわせて、イテレーション総括.md(v1.0)6章の残課題のうち、次を今回のスコープに含めて対応する。
- ★R1: 起動エラー画面(データベース破損時)に、エクスポートファイルを選択して復元する導線を追加する
- ★D3: 取引先にフリガナ項目を追加し、一覧を五十音順で表示できるようにする
- SEC-07: electron-builderの除外設定を見直し、配布物に含まれる不要な同梱ファイルを整理する
- ★D1: アプリアイコンをゼロから制作する(モチーフ・配色等の具体的な方向性はデザインフェーズでヒアリングする)

一方、次の項目は今回のスコープ外とし、次回以降のイテレーションへ持ち越す。
- 入出金・経費の記録、案件管理、タスク・期限管理(イテレーション総括.md v1.0 7章の優先度B〜D)
- SEC-04(Electron Fuses・署名)、SEC-05(暗号化)、SEC-06(未署名配布)
- ★D2(Node.jsバージョンの完全一致)、BUG-03(IPCエラーメッセージの文言、参考所見)
- テストエビデンスの運用課題(結合シナリオ再実行時の証拠画像上書き)は、次回tester着手時に対応要否を判断する

詳細な機能範囲の線引き(画面項目・入出金/経費機能との連携範囲等)は、次フェーズのplannerが作成するプロジェクト計画書にて確定する。

## 7. 要確認事項・未解決事項

- ★7(インボイス登録状況)・★8(電子帳簿保存法への対応範囲)は、本イテレーションのスコープ確認により5章のとおり方針が確定したため、解消済みとする。
- 見積書・請求書のPDFレイアウト(適格請求書等保存方式・区分記載請求書等それぞれの具体的な項目配置)、電子帳簿保存法対応の検索方式の実装詳細は、設計フェーズ(architecture)にて確定する。
- ★D1(アプリアイコン)の具体的なデザイン(モチーフ・配色等)は、デザインフェーズでdesignerがヒアリングのうえ確定する。
- SEC-04〜SEC-06(Electron Fuses・コード署名、暗号化、未署名配布)、および案件管理・入出金経費・タスク管理等の持ち越し機能の対応要否・着手時期は、次回以降のiteration-startで改めて確認する。
- 見積書・請求書と「取引先管理」「入出金・経費」等、他機能との項目連携の詳細な線引きは、次フェーズのplannerが作成するプロジェクト計画書にて確定する。
