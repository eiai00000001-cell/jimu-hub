# プロジェクト概要

## 1. 文書情報

- 作成日: 2026-09-28
- 版数: v3.0
- 対象イテレーション: イテレーション2(入出金・経費の記録+取引先の復帰・下書き削除)
- 参照元: イテレーション総括.md v3.0(docs/10_summary。6章・7章)、スコープ確認結果(2026-10-04)。アイデアメモ.mdは今回追記なし

## 2. プロジェクトの目的・背景

「事務HUB」は、個人事業主である依頼者ご本人が日々行う事務作業を一つのツールに集約し、効率的に管理できるようにすることを目的として開発する。対象とする業務は、見積書・請求書の作成、入出金・経費の記録、取引先・案件の管理、タスク・期限の管理である。現時点でこれらの業務を管理している既存ツールは無く、今回新規に構築するものであり、既存システムからのデータ移行は発生しない。

## 3. 対象ユーザー・利用シーン

- 利用者: 依頼者ご本人のみ(唯一の利用者であり、複数ユーザーでの利用は想定しない)
- 利用端末: PCを中心とする
- 想定利用シーン: 見積書・請求書の作成、日々の入出金・経費の記録、取引先や案件情報の参照・更新、タスクや期限の管理など、個人事業の運営に伴う事務作業全般

## 4. 技術スタック・制約(初回確定分)

- 提供形態: インターネットには公開せず、ローカル環境のみで動作するデスクトップアプリケーションとする。
- 認証: 認証機能は設けない方針とする。PC自体のログイン・画面ロックによって保護することとする。ヒアリング当初は「ログイン必須」案も挙がったが、ローカル専用のデスクトップアプリであるという特性を踏まえ、「認証なし」に決定した。
- 具体的な使用言語・フレームワーク・データベース等の技術選定は、イテレーション0の設計フェーズ(基本設計書.md・詳細設計書.md)にて確定済みであり、イテレーション1以降はこれを前提として踏襲する。イテレーション1のPDF出力機能の技術要素も確定済みであり、同様に踏襲する。イテレーション2で新たに必要となる技術要素(領収書ファイルの保存方式、CSV出力の形式・文字コード等)の選定は、次フェーズ(architecture)にて確定する。
- デザイン担当: designer(業務用のデスクトップツールであり、デザイン重視の制作案件ではないため。イテレーション1の実績を継続する)。

## 5. セキュリティ・法令面の方針

- インボイス制度(適格請求書等保存方式)への対応: イテレーション総括.md(v1.0)で申し送られていた依頼者のインボイス登録状況(★7)について、イテレーション1のスコープ確認で「登録・未登録の両方に対応する」方針が確定した。設定画面にインボイス登録番号を入力した場合にのみ、見積書・請求書に適格請求書等保存方式の記載事項(登録番号等)を表示する。登録番号が未入力の場合は、区分記載請求書等の形式で出力する。
- 電子帳簿保存法への対応: ★8について、最小限の対応水準として「発行した見積書・請求書等の文書を改変せずに保存し、日付・金額・取引先の各条件で検索できるようにする」方針が確定した(イテレーション1で実装済み)。イテレーション2では、この水準(改変検知、日付・金額・取引先での検索)を入出金・経費の記録にも適用し、添付する領収書ファイル(PDF・画像)も同水準で扱う。詳細な保存形式・検索方式は設計フェーズで確定する。
- 見積書・請求書の出力形式: PDF保存のみとする(印刷は依頼者ご本人がPDFを開いて行う運用とし、アプリ側に印刷機能は設けない)。
- バックアップ: 手動エクスポート方式とし、エクスポートしたデータからの復元も可能な構成とする。起動エラー画面からの復元導線(★R1)は本イテレーションで追加する(6章参照)。
- 取引先の氏名・連絡先や金銭に関する情報に加え、見積書・請求書には依頼者ご自身の事業者情報(氏名・屋号、住所)や振込先口座情報も記載されるため、これらの取り扱いにも十分留意する。

## 6. 今回のイテレーションの位置づけと対象スコープの概要

イテレーション2は、イテレーション総括.md(v2.0)7章で優先度Aとされた「入出金・経費の記録」を主対象とし、あわせて依頼者ご本人のご要望である★N1・★N2を含める。イテレーション1(見積書・請求書作成)は完了しており、番号は継続してイテレーション2とする。

主要機能として、次を含む。
- 入出金・経費の記録(入力・一覧・検索を前提とする)
  - 請求書を「入金済み」にしたとき、入金記録を自動作成する(金額・取引先を引き継ぐ)
  - 勘定科目(経費の区分)の設定
  - 領収書の添付(PDF・画像)
  - 月別・年別の集計
  - CSV出力(確定申告・会計ソフト取り込み用)
  - 電子帳簿保存法への対応: イテレーション1の最小限の水準(改変検知、日付・金額・取引先での検索)を入出金・経費の記録および領収書添付ファイルにも適用する(5章参照)
- ★N1: 利用停止にした取引先を「利用中」へ戻す機能。戻した時点で、見積書・請求書の選択肢にただちに復帰させる
- ★N2: 下書きの見積書・請求書の削除。確認画面を表示したうえで完全に削除する。PDF保存済みの書類は、電子帳簿保存法の考え方に沿って、削除不可の仕様を維持する

一方、次の項目は今回のスコープ外とし、次回以降のイテレーションへ持ち越す。
- 案件管理(優先度B)、タスク・期限管理(優先度C)
- SEC-04(Electron Fuses・署名)、SEC-05(暗号化)、SEC-06(未署名配布)。★14(持ち越し課題の対応要否・着手時期)は、今回のスコープ確認で「今回は持ち越し」と確定した
- SEC-08の残存分(過去のGit履歴に残るパス。リスク受容を継続)
- レビュー参考R-01〜R-13の未対応分(R-04を含む)、★D2(Node.jsバージョンの完全一致)、参考O3・O4、BUG-03(IPCエラーメッセージの文言、参考所見)
- ★D3の運用分(既存の取引先へのフリガナ入力)は、依頼者ご本人の入力による対応とする

なお、「自社情報」の名称は変更しない(依頼者ご本人のご意向。イテレーション1から継続)。

詳細な機能範囲の線引き(画面項目、請求書の入金ステータスと入金記録の連携の細部〔入金済みを取り消した場合の扱い等〕、勘定科目の初期値・追加可否、集計の切り口等)は、次フェーズのplannerが作成するプロジェクト計画書にて確定する。

## 7. 要確認事項・未解決事項

- ★7(インボイス登録状況)・★8(電子帳簿保存法への対応範囲)は、イテレーション1で解消済みである。★14(持ち越し課題の対応要否)は、今回のスコープ確認で「今回は持ち越し」と確定したため、解消済みとする。
- 入出金・経費に関する詳細(入金記録の自動作成の細部、勘定科目の初期値・追加可否、領収書ファイルの保存方式、集計の切り口、CSVの項目・文字コード等)は、plannerの計画書および設計フェーズ(architecture)にて確定する。電子帳簿保存法対応の検索・改変検知方式の実装詳細も、設計フェーズで確定する。
- SEC-04〜SEC-06(Electron Fuses・コード署名、暗号化、未署名配布)、案件管理・タスク・期限管理等の持ち越し項目は、次回以降のiteration-startで改めて確認する。
- 入出金・経費と「取引先管理」「見積書・請求書」等、他機能との項目連携の詳細な線引きは、次フェーズのplannerが作成するプロジェクト計画書にて確定する。
