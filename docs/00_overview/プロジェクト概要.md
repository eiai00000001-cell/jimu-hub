# プロジェクト概要

## 1. 文書情報

- 作成日: 2026-09-26
- 版数: v1.0
- 対象イテレーション: イテレーション0(プロジェクト方針・基盤構築)

## 2. プロジェクトの目的・背景

「事務HUB」は、個人事業主である依頼者ご本人が日々行う事務作業を一つのツールに集約し、効率的に管理できるようにすることを目的として開発する。対象とする業務は、見積書・請求書の作成、入出金・経費の記録、取引先・案件の管理、タスク・期限の管理である。現時点でこれらの業務を管理している既存ツールは無く、今回新規に構築するものであり、既存システムからのデータ移行は発生しない。

## 3. 対象ユーザー・利用シーン

- 利用者: 依頼者ご本人のみ(唯一の利用者であり、複数ユーザーでの利用は想定しない)
- 利用端末: PCを中心とする
- 想定利用シーン: 見積書・請求書の作成、日々の入出金・経費の記録、取引先や案件情報の参照・更新、タスクや期限の管理など、個人事業の運営に伴う事務作業全般

## 4. 技術スタック・制約(初回確定分)

- 提供形態: インターネットには公開せず、ローカル環境のみで動作するデスクトップアプリケーションとする。
- 認証: 認証機能は設けない方針とする。PC自体のログイン・画面ロックによって保護することとする。ヒアリング当初は「ログイン必須」案も挙がったが、ローカル専用のデスクトップアプリであるという特性を踏まえ、「認証なし」に決定した。
- 具体的な使用言語・フレームワーク・データベース等の技術選定は、以降の設計フェーズ(architecture)にて確定する。

## 5. セキュリティ・法令面の方針

- インボイス制度(適格請求書等保存方式)への対応: 見積書・請求書がインボイス制度の記載要件を満たせるようにする。依頼者のインボイス登録状況は現時点で未定のため、登録番号は任意入力項目とし、登録済み・未登録いずれの状態でも利用できるようにする。
- 電子帳簿保存法への対応を考慮したデータ保存・管理を行う。
- バックアップ: 手動エクスポート方式とし、エクスポートしたデータからの復元も可能な構成とする。
- 取引先の氏名・連絡先や金銭に関する情報など、個人情報・機微情報を取り扱うため、取り扱いには十分留意する。

## 6. 今回のイテレーションの位置づけと対象スコープの概要

イテレーション0は、事務HUB全体の土台となる「アプリ基盤(デスクトップアプリとしての骨格、データ保存方式、バックアップ・復元方針等)」と「取引先管理」機能を対象とする。

ヒアリング当初は「基盤+ログイン+取引先管理」を想定していたが、上記4章のとおり認証なし方針に決定したことに伴い、実質的なスコープは「アプリ基盤+取引先管理」となる。

見積書・請求書の作成、入出金・経費の記録、案件管理、タスク・期限管理については、以降のイテレーションで順次対応する候補とする。なお、詳細な機能範囲の線引きは、次フェーズのplannerが作成するプロジェクト計画書にて確定する。

稼働時期については特に期限を設けず、順次進める方針とする。

## 7. 要確認事項・未解決事項

- インボイス登録状況(実際に登録済みか否か)は依頼者側で現時点未定である。判明次第、登録番号入力欄の扱い(任意項目のままとするか等)を再確認する。
- データの保存形式・保存場所、バックアップ(手動エクスポート)の具体的なファイル形式・操作手順は本書の対象外とし、設計フェーズ(architecture)にて確定する。
- 「取引先管理」と、以降のイテレーションで扱う「案件管理」「見積・請求書」「入出金・経費」「タスク・期限管理」との項目連携(取引先情報の参照関係等)の詳細な線引きは、次フェーズのplannerが作成するプロジェクト計画書にて確定する。
