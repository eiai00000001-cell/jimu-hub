## 2. デザインの方向性(ヒアリング結果の反映)

依頼者ご本人より、以下の方向性でデザインを進めるとのご確認をいただいている。

- 雰囲気: macOS標準アプリに馴染む見た目(サイドバー、システムフォント等)とする
- 配色: グレー・モノトーンを基調とし、差し色も色味を抑えた落ち着いた印象にする
- ダークモード: 対応しない(ライト表示のみ)
- 支給素材: なし(ロゴ・写真等の指定なし)
- 参考サイト・アプリ: 指定なし

上記を踏まえ、業務用途で長時間使っても疲れにくい、抑えた配色・システムフォントを採用する。

## 3. カラーパレット

### 3.1 v0.8改訂の背景

v0.7までの間に、ユーザー修正依頼を重ねた結果、意味色を含めて配色の種類が10種類ほどに増え、ボタン・入力欄・メッセージ・バッジがいずれも似た角丸(6px)・似た枠線色で構成されていたため、部品同士の見分けがつきにくくなっていた(特に成功メッセージの背景`#B4B4B7`がボタンの色と近く紛らわしいとのご指摘があった)。v0.8では、色を6色のみに絞り込み、部品を「押せる物・書き込む物・読むだけの物・表示だけの物・入れ物」のカテゴリーに整理し、カテゴリーごとに形(角丸の有無)と色の使い方を統一することで、見た目のわかりやすさを優先する方針に転換した。

### 3.2 使用する6色

| 色名 | カラーコード | 用途 |
|---|---|---|
| 白 | `#FFFFFF` | パネル・カード・ダイアログ・入力欄の地、ヘッダーの帯(サイドバーのアプリ名エリア・コンテンツ見出し)、メッセージの地 |
| 背景グレー | `#F2F2F4` | ウィンドウ全体・サイドバーの背景(サイドバーは専用の背景色を持たず、ウィンドウと同じ背景グレーを区切り線で分けて使う)、表の見出し行、「利用中」バッジ・「準備中」バッジの地 |
| 罫線グレー | `#D1D1D6` | パネル・入力欄・ボタン(副)など、すべての枠線・区切り線 |
| 補助グレー | `#6E6E73` | ラベル・補足説明・プレースホルダー、「準備中」メニューの文字、「準備中」バッジの文字 |
| 濃グレー | `#3A3A3C` | 本文の文字、主ボタンの塗り、選択中のサイドバー項目の塗り、成功メッセージの左帯とアイコン、「利用停止」バッジの塗り |
| 赤 | `#B3453A` | エラー・警告メッセージの左帯とアイコン、データ復元(全置換・取り消し不能)の警告ボタン、入力エラーの枠 |

上記6色はいずれもユーザー指定の値をそのまま採用しており、本文・見出し等の主要な文字色の組み合わせでコントラスト比を確認した上で、調整なしで問題ないことを確認している(例: 濃グレー`#3A3A3C`と白`#FFFFFF`は11.4:1、補助グレー`#6E6E73`と背景グレー`#F2F2F4`は4.5:1、赤`#B3453A`と白`#FFFFFF`は5.5:1で、いずれもWCAG AA基準(通常文字4.5:1)を満たす)。

**例外(6色以外を使う3箇所)**:
1. タイトルバーの信号ボタン(赤・黄・緑): macOSウィンドウ標準の配色であり、アプリ独自の意味色ではない
2. モックアップ外側の背景: 見本を框で囲むための表示用の背景であり、実際のアプリ画面には存在しない
3. 影・オーバーレイの暗幕: `box-shadow`やモーダル背景の半透明オーバーレイに使う`rgba(0,0,0,x)`。新しい色を定義するものではなく、黒の透明度による表現

**状態(ホバー等)の表現方法**: ホバー・フォーカスなどの状態変化のために新しい色を作らず、既存6色の透明度(`rgba()`)や、枠線の太さ変更(フォーカス時2px等)で表現する。必須項目のマークも赤ではなく、補助グレーで「必須」と文字表記する(旧来の赤い「*」等は廃止)。

**廃止した旧来の色**: `#1D1D1F` `#4A4A4A` `#333333` `#ECECEE` `#D9D9DE` `#C7C7CC` `#AEAEB2` `#E2E2E5` `#B4B4B7` `#7F7F81` `#FBECEB` `#E3B6AE` 等は、v0.8以降使用しない。

### 3.3 適用状況

v0.8の試作(`F-00_components.html`・`F-04_client-new.html`)をユーザーが承認したことを受け、v0.9で残る6画面(F-01・F-02・F-03・F-05・F-06・F-07)にも新しい6色・部品カテゴリーのルールを展開した。**v0.9時点で、`mockups/`配下の全8ファイル(F-00〜F-07)が新ルールに統一されている。** 各HTMLの`:root`で定義する色変数もすべて6色(白・背景グレー・罫線グレー・補助グレー・濃グレー・赤)に揃え、3.2節で「廃止」とした旧来の色は描画には使用していない(廃止色の一覧を説明目的でテキストとして記載している箇所を除く)。

## 4. フォント

外部フォントには依存せず、OS標準のシステムフォントのみを使用する。

```css
font-family: -apple-system, BlinkMacSystemFont, "Hiragino Sans",
  "Hiragino Kaku Gothic ProN", "Yu Gothic", "Helvetica Neue", Arial, sans-serif;
```

- 見出し: 太字(600〜700)、サイズは画面タイトルで18px前後、ダイアログ見出しで15px前後。サイドバー左上のアプリ名「事務HUB」も画面タイトルと同じ18px・600とし、両者が同格の見出しに見えるよう統一する
- 本文・ラベル・ボタン: 通常(400〔本文〕〜500〔ボタン〕)、基準サイズ13px。macOS標準アプリの文字サイズ感に合わせ、小さめの補助テキストは11〜12pxとする
- 和文・英数字とも同一のシステムフォントスタックで統一し、Web標準フォントのみで完結させる(外部CDN・Webフォント配信は使用しない)

## 5. 基本トーン

### 5.1 部品カテゴリーのルール(v0.8で導入、v0.9で全画面に適用)

部品を「押せる物・書き込む物・読むだけの物・表示だけの物・入れ物」のカテゴリーに分け、カテゴリーごとに形(角丸の有無)と色の使い方を統一する。**原則: 角丸は「押せる物」(ボタン)にのみ付ける。** 状態バッジ(丸型)とウィンドウ外枠(OS表現)は例外として別の角丸を持つが、それ以外(入力欄・メッセージ・パネル/カード/ダイアログ・サイドバー項目)はすべて直角(`border-radius: 0`)とする。

| カテゴリー | 具体例 | 角丸 | 見た目のルール |
|---|---|---|---|
| 押せる物(ボタン) | 主ボタン・副ボタン・危険ボタン | 6px | 高さ32px。主=濃グレー`#3A3A3C`塗り+白文字/副=白地+罫線グレー枠+濃グレー文字/危険=赤`#B3453A`塗り+白文字(データ復元のダイアログのみに使用) |
| 押せる物(テキストリンク) | 「← 一覧へ戻る」等 | なし(枠自体がない) | 枠なし、下線付きの文字(濃グレー) |
| 書き込む物(入力欄) | テキスト入力・検索欄・選択欄(select)・複数行入力(textarea) | 0(直角) | 高さ32px(複数行は内容に応じて可変)。白地+罫線グレー枠。フォーカス時は濃グレー2px枠、エラー時は赤枠。すべての入力系部品で共通のルールとする |
| 読むだけの物(メッセージ) | 完了・エラー・警告メッセージ | 0(直角) | 枠(外周)なし、白地+左4pxの帯+アイコン。成功=濃グレーの帯とアイコン(✓)、エラー・警告=赤の帯とアイコン(!)。本文の文字は種別に関わらず常に濃グレーとする(帯とアイコンの色だけで種別を示す) |
| 表示だけの物(状態バッジ) | 利用中・利用停止・準備中 | 999px(丸型、例外) | 利用中=背景グレー地+濃グレー文字/利用停止=濃グレー塗り+白文字/準備中=背景グレー地+補助グレー文字(※)。文字数に関わらず1行で収め、折り返さない(`white-space: nowrap`) |
| 入れ物(パネル・カード・ダイアログ) | 詳細パネル・サマリーカード・モーダルダイアログ | 0(直角) | 白地+罫線グレー枠。影(box-shadow)はダイアログのみに付け、パネル・カードには付けない |
| サイドバー項目 | メニュー項目 | 0(直角) | サイドバー全幅(左右の余白・マージンなし)。選択中は濃グレー塗り+白文字。v0.6で確定した全幅化・縦位置揃えの構成はそのまま維持する |
| ウィンドウ外枠 | アプリウィンドウ全体 | 10px(例外) | macOSのウィンドウらしさを出すためのOS表現として維持し、上記ルールの対象外とする |

※「準備中」バッジは、サイドバーのように地自体が背景グレーの場所に置くと同化して見えなくなるため、その場合に限り白地+補助グレー文字にする(v0.9でレビュー指摘を受け反映)。

必須項目の表記は赤色のマークをやめ、補助グレーで「必須」と文字表記する。ホバー・フォーカス等の状態変化は新しい色を作らず、既存6色の透明度(`rgba()`)や枠線の太さ変更で表現する。メッセージ(読むだけの物)は、白地のまま余白のない場所に直接置くと背景と区別しにくいため、実装上は背景グレーの領域(ウィンドウ本体やダイアログ内側など)の上に配置することを前提とする。フォーム内の入力欄を複数列に並べる場合は、列ごとに`flex: 1`等で幅を揃え、特定の列だけ狭くならないようにする(v0.9でレビュー指摘を受け反映)。

### 5.2 その他の基本トーン

- **余白**: 画面の内側余白は24px前後、フォーム項目間は16px前後を基本とし、詰め込みすぎない落ち着いた密度にする
- **ウィンドウ表現**: モックアップはタイトルバー(信号ボタン付き)+左サイドバー+コンテンツ領域という、macOSデスクトップアプリらしいウィンドウ構成で統一する。左サイドバーはトップ画面に限らず全画面で常時表示し、先頭に配置する「ホーム」メニューから、どの画面からでもトップ画面へ戻れるようにする(ユーザー確認済み)。ウィンドウの高さは各画面の実際のコンテンツ量に合わせて可変とし、内容に対して不自然な余白が生じないようにする。ただしエクスポート・復元ダイアログ(モーダルオーバーレイで表示する画面)は、モーダル本体が背後のページ(通常フローの一部ではない絶対配置要素)の高さに影響されないため、通常のコンテンツ量に基づく可変ロジックだけではモーダルの内容(タイトル〜末尾のメッセージ例まで)を欠けなく収められない場合がある。この2画面に限り、モーダル全体+上下の適切な余白が収まる`min-height`(モックアップでは560px)をウィンドウに設定し、モーダルを画面内に確実に収める
- **画面名の表記**: コンテンツ領域ヘッダーの見出しには、その画面固有の名称を表示する(トップ画面は「ホーム」、取引先一覧は「取引先管理」、取引先詳細は「取引先詳細」等)。「事務HUB」はアプリ名としてサイドバー左上にのみ表示し、画面見出しとしては使用しない。タイトルバー中央の表記も「事務HUB - 〈画面名〉」の形式(例: 「事務HUB - ホーム」「事務HUB - 取引先一覧」)で全画面統一する
- **サイドバーとコンテンツヘッダーの縦位置合わせ**: サイドバー上部のアプリ名領域と、コンテンツ領域のヘッダー(画面タイトルの帯)は、共通のCSS変数`--header-height`(`56px`)で高さを揃え、いずれもタイトルバー直下からパディングなしで開始する。これにより、両者の下端の区切り線が横一直線に並び、サイドバーメニューの先頭項目(選択状態の背景)の上端がその区切り線とぴったり揃う。実装時もこの1つの変数を変更するだけで両方の高さが連動するため、画面追加時にずれが生じにくい(v0.8でも変更なし)
