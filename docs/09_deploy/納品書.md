### 2.1 今回のイテレーションで追加・変更した主な内容

- **タスク・期限管理**(F-34〜F-38): やるべきことを「タスク」として、名前・メモ・期限日・案件(任意)とともに登録できます。完了・未完了の切り替え、削除、状態・案件・期限・キーワードでの絞り込み、未完了と期限超過の件数表示に対応しています。期限を過ぎた未完了のタスクは、赤字・「期限超過」の文字・「!」のしるしで、色だけに頼らずに示されます。案件の詳細画面にも、紐づくタスクが表示されます。左のメニューの「タスク・期限」(これまで「準備中」でした)から使えます。
- **案件を削除したときのタスクの扱い**(R-54): 案件を削除しても、紐づくタスクは消えず「案件なし」に戻ります。削除前の確認画面に件数が表示されます。
- **バックアップ・復元へのタスクの追加**(F-39): タスクも、エクスポート・復元の対象になりました。0.4.0以前のファイルを復元すると、現在のタスクが消えるため、復元前の確認画面でお知らせします(R-55)。
- **データベースの新しい版への自動移行**(版 5 → 6): 初めて0.5.0を起動すると、タスクの保管場所が自動で追加されます。移行の直前のデータは自動で保存されます(`backups/pre-migration_v5_<日時>.sqlite`。直近3回分)。これまでの取引先・書類・記録・領収書は変わりません。
- **復元時の検証の強化**(SEC-23): 細工されたファイルを復元しても、タスクの番号・日時が不正な場合は復元を中止し、現在のデータを変えません。また、確認画面の表示と実際の復元内容が一致するようにしました。
- **Electronの更新**(SEC-22): アプリの土台であるElectronを44.5.1から44.8.0へ更新しました(上流の修正の取り込み)。
- **開発の安全対策**(依頼者のMacには影響しません): 個人のパス・メールアドレス等の混入を、コミット時に自動で検査する仕組み(pre-commit)の導入、テスト作業フォルダの固定(`.e2e-work/`)と後片付けの自動化(`check:work`・`clean:work`)。前回までの課題(SEC-14・SEC-18・SEC-19の再発防止)への対応です。

## 5. セットアップ手順

このアプリは、依頼者ご本人のMacに直接インストールしてお使いいただくローカル完結型のデスクトップアプリです。インターネット環境は不要です。

- インストール・既存の0.4.0以前からの更新手順は、操作マニュアル.md 2章に記載しています。**更新の前に、現在の事務HUBでデータのエクスポートを行ってください。**
- 初回起動時は、署名・公証を行っていないため、macOSの警告が表示されます。操作マニュアル.md 2.4章の手順(「システム設定」→「プライバシーとセキュリティ」→「このまま開く」)で許可してください。この手順は、イテレーション2(0.3.0)に依頼者ご本人のMacで確認済みです。なお、「アイコンを右クリックして『開く』を選ぶ」方法は、最近のmacOSでは使えないため、案内していません。
- 起動時に、データの形式が自動的に新しい版へ移行されます(データベースの版 5 → 6)。移行の直前のデータは自動で保存されます(`backups/pre-migration_v5_<日時>.sqlite`。直近3回分)。この移行は自動テストで確認済み(旧版〔0.4.0〕の定義で作ったデータ、および配布版で確認)です。依頼者ご本人のデータのコピーでの確認はTC-157(任意。未実施)です。
- 開発作業を引き継ぐ場合の手順(`npm ci`、`npm run dev`、`npm run dist:mac`等。開発機の初期設定として`brew install gitleaks`とpre-commitの有効化を含む)は、README.md 3章に記載しています。このうち`npm run dist:mac`(配布用`.dmg`の作成)は、本納品フェーズでも実際に実行し、成功を確認しました(6章参照)。あわせて、型チェック(`npm run typecheck`)と単体テスト(`npm test`。120ファイル・1242件)も、アプリ版数を0.5.0へ更新した状態で実行し、成功を確認しました。作業終了後に`npm run check:work`が「残骸はありません」であることも確認しています。その他の開発用コマンドは前フェーズで実行・確認済みのもので、本フェーズでは再実行していません。
