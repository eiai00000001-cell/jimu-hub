## 3. 機能実装状況

機能仕様書・詳細設計書のF-01〜F-08は、すべて実装済みです。テスト結果報告書.md v0.1のとおり、対応するテストケースはすべて合格しています。

| 機能ID | 機能名 | 実装状況 | 補足 |
|---|---|---|---|
| F-01 | トップ画面(ダッシュボード) | 実装済み | サイドメニュー・取引先登録件数(利用中)表示・データ管理導線。データベース破損時の起動エラー画面表示も正常に動作します(TC-02合格)。ただし、そのエラー画面から復元操作を行う導線は今回未実装です(4章★R1参照) |
| F-02 | データエクスポート | 実装済み | JSON書き出し、保存先パスを含む完了メッセージ表示。実機でOS標準保存ダイアログ(初期フォルダ「書類」・初期ファイル名)まで確認済みです |
| F-03 | データ復元 | 実装済み | 全置換方式、復元前の自動退避コピー(直近3世代保持)、失敗時の自動復旧。実機でファイル選択ダイアログの`.json`絞り込みまで確認済みです |
| F-04 | 取引先の登録 | 実装済み | 入力バリデーション、登録後は一覧画面へ遷移 |

| F-06 | 取引先の参照(詳細表示) | 実装済み | 全項目表示 |

## 4. 既知の制限事項・未確定事項

各フェーズの成果物に記載された要確認事項・未解決事項を、重複を整理したうえで一本化したものです。内容の解決・確定はここでは行っておらず、そのまま引き継いでいます。

| No | 内容 | 影響 | 今後の対応方針(目安) | 出典 |
|---|---|---|---|---|
| ★D1 | アプリアイコンが既定のまま(electron-builderの既定アイコン) | 配布物の見た目のみで、機能には影響しません | 次回以降、アイコン素材の準備方針をご相談のうえdesignerに依頼する | README.md 7章 |
| ★D2 | 一部の開発用パッケージが推奨するNode.jsバージョンと、動作確認に使用したバージョンが完全には一致しない(現時点で機能上の問題は未確認) | 現時点では機能への影響はありません | 次回Node.jsバージョンアップ時にあらためて動作確認する | README.md 7章 |
| ★D3 | 取引先一覧の並び順(名称昇順)は、フリガナ情報を持たないため、漢字を含む名称で字典的な五十音順と一致しない場合がある | 一覧の並び順の見え方のみで、データ自体には影響しません | フリガナ項目の追加要否を次回イテレーションでご確認いただく | README.md 7章 |
| ★R1 | 起動エラー画面(データベース破損時)に、復元操作を行うボタン・導線が実装されていない | データベースファイルが破損し、かつバックアップ(エクスポートファイル)をお持ちの場合でも、アプリの画面上だけでは復旧できません。操作マニュアル6章に手動での対処手順を記載しています | 次回イテレーションの要件・設計確認の中で、対応するかどうか(画面に復元導線を追加する案、または案内文言を実際の機能範囲に合わせて見直す案)をご確認いただく | レビュー結果報告書.md v0.2、テスト結果報告書.md v0.1 |
| SEC-04 | Electron Fusesが初期設定のまま。配布物は簡易署名(ad-hoc署名)にとどまる | 同じパソコン上で任意のコマンドを実行できる方がいる場合、想定より高い操作ができる可能性があります。ただしその状況では元々データファイルを直接読める状態のため、新たに増えるリスクは小さいと判断されています | 次回以降、Fuses設定の見直しと署名のやり直し、実機での起動確認をあわせて実施する | セキュリティチェック結果報告書.md v0.0 |
| SEC-06 | 未署名配布のため、配布物が途中で差し替えられても利用者側では気づけない | 受け渡し経路に注意が必要です | 本書6章にSHA-256を記載し、受け渡しは依頼者ご本人と直接やり取りできる経路に限定する(今回はこの案内で対応済み) | セキュリティチェック結果報告書.md v0.0 |
| SEC-07 | 配布物に他OS用のネイティブバイナリ等、不要な同梱物が含まれている | 機微情報は含まれず、配布サイズが増えるのみです | 次回developer着手時に、electron-builderの除外設定を追加する | セキュリティチェック結果報告書.md v0.0 |
| BUG-03 | IPC境界のエラーメッセージに技術的な文言が残る箇所がある(参考所見) | 実害は小さいと判断されています | 対応不要のまま記録のみ(今回は対応していません) | テスト結果報告書.md v0.1(TC-24) |
| ★7 | インボイス登録状況(登録済みか否か)が依頼者側で未定 | 見積・請求機能での登録番号欄の扱いに影響します(今回の取引先管理への影響は小さいです) | 見積・請求機能のイテレーション着手前にご確認いただく | 要件定義書.md v0.1 |
| ★8 | 電子帳簿保存法への対応範囲(対象とする記録・書類、保存要件の水準)が未確定 | 見積・請求、入出金・経費の各機能の要件に影響します | 該当機能のイテレーション着手前にご確認いただく | 要件定義書.md v0.1 |
| ★9 | 次イテレーション以降の機能の優先順位が未確定 | 以降の開発計画に影響します | イテレーション0の総括時にご確認いただく(project-leader) | 要件定義書.md v0.1 |

なお、SEC-05(データベース・退避コピー・エクスポートファイルが暗号化されていない点)は、今回は暗号化を行わない方針をご確認済みのため、操作マニュアル.md 5章の案内(FileVaultとログインパスワード等の4項目)で補っています。今後、暗号化を実装するかどうかは次回以降の機能追加の候補です。

## 5. セットアップ手順

このアプリは、依頼者ご本人のMacに直接インストールしてお使いいただくローカル完結型のデスクトップアプリです。サーバーへの接続やインターネット環境は不要です。

- インストール方法・初回起動時の確認手順は、操作マニュアル.md 2章に詳しく記載しています(本納品にあたり実機で再現確認済みです。8章参照)。
- 今後、機能追加等の開発作業を引き継ぐ場合に必要な手順(`npm install`、`npm run dev`、`npm run dist:mac`等)は、README.md 3章に記載しています。このうち`npm run dist:mac`(配布用`.dmg`の作成)は、本納品フェーズでも実際に実行し、成功することを確認しました(6章参照)。その他の開発用コマンドは、前フェーズ(実装・テスト・セキュリティ)で developer・tester・security-expert が実行し成功を確認済みのもので、本フェーズでは再実行していません。

2026-09-27、依頼者ご本人のMac(macOS 26.6)にて、上記`.dmg`を用いて実機確認を行いました。いずれも問題は見つかりませんでした。

| 確認項目 | 結果 |
|---|---|
| `.dmg`のマウント、Applicationsフォルダへのインストール(★T4) | 問題なし |
| 初回起動時のGatekeeper警告と許可手順(★T3) | 問題なし。手順は操作マニュアル.md 2章に記載(警告を閉じる→「システム設定 > プライバシーとセキュリティ」の「このまま開く」→パスワード入力→もう一度「このまま開く」。右クリックで「開く」を選ぶ方法は、最近のmacOSでは使えないことを確認済み) |
