### 2.1 今回のイテレーションで追加・変更した主な内容

- **案件管理**(F-27〜F-31): 仕事(案件)を登録し、見積書・請求書・入出金・経費を案件に紐づけて、案件ごとの売上・経費・差引を確認できます。紐づけの付け替えは履歴に残り、付け替えても書類・記録の本体は変わりません。案件の完了・再開、検索にも対応しています。
- **バックアップ・復元のメモリ改善**(F-32。前回からの課題★T3⑤・SEC-16の解消): 領収書が多くてもMacのメモリを使いすぎないように、1件ずつ書き出し・読み込む方式へ見直しました。開発用Macでの実測では、1GiB規模の復元でも、アプリ本体のメモリの増加は約7MBでした(前回は約2.3〜2.7GB)。進み具合も表示されます。
- **旧形式のバックアップを復元するときの確認画面**(F-33。前回の★T4・SEC-15の解消): 領収書や案件を含まない古いファイルを復元すると、現在の領収書・案件が消える場合に、事前に1つの確認画面でお知らせし、同意いただいてから復元します。
- エクスポート・復元が、案件と案件への紐づけにも対応しました(データベースの版 4 → 5。起動時に自動で移行され、移行の直前のデータは自動で保存されます)。
- 開発ツールの脆弱性への対応(`npm audit fix`。SEC-17の解消)と、配布物から不要な同梱物(他のOS用の部品)を取り除く設定の追加(BUG-01(i3)の修正)を行いました。

## 5. セットアップ手順

このアプリは、依頼者ご本人のMacに直接インストールしてお使いいただくローカル完結型のデスクトップアプリです。インターネット環境は不要です。

- インストール・既存の0.3.0以前からの更新手順は、操作マニュアル.md 2章に記載しています。**更新の前に、現在の事務HUB(0.3.0)でデータのエクスポートを行ってください。**
- 初回起動時は、署名・公証を行っていないため、macOSの警告が表示されます。操作マニュアル.md 2.4章の手順(「システム設定」→「プライバシーとセキュリティ」→「このまま開く」)で許可してください。この手順は、前回(0.3.0)に依頼者ご本人のMacで確認済みです。なお、「アイコンを右クリックして『開く』を選ぶ」方法は、最近のmacOSでは使えないため、案内していません。
- 起動時に、データの形式が自動的に新しい版へ移行されます(データベースの版 4 → 5)。移行の直前のデータは自動で保存されます(`backups/pre-migration_v<版>_<日時>.sqlite`。直近3回分)。この移行は自動テストで確認済み(旧版〔0.3.0〕の構造のデータで確認)です。依頼者ご本人のデータのコピーでの確認はTC-130(7章)です。
- 開発作業を引き継ぐ場合の手順(`npm install`、`npm run dev`、`npm run dist:mac`等)は、README.md 3章に記載しています。このうち`npm run dist:mac`(配布用`.dmg`の作成)は、本納品フェーズでも実際に実行し、成功を確認しました(6章参照)。あわせて、型チェック(`npm run typecheck`)と単体テスト(`npm test`。987件)も、アプリ版数を0.4.0へ更新した状態で実行し、成功を確認しました。その他の開発用コマンドは前フェーズで実行・確認済みのもので、本フェーズでは再実行していません。
