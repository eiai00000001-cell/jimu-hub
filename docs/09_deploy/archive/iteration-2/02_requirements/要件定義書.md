## 3. 背景・目的

「事務HUB」は、個人事業主である依頼者ご本人が日々行う事務作業(見積書・請求書の作成、入出金・経費の記録、取引先・案件の管理、タスク・期限の管理)を一つのツールに集約し、効率的に管理できるようにすることを目的として開発する(プロジェクト計画書 2.2章・3.1章)。

イテレーション0では、以降の機能を載せていく土台となる「アプリ基盤」と、以降の各機能から参照される共通の台帳としての「取引先管理」を整備した(完了。イテレーション総括.md v1.0参照)。

イテレーション1では、イテレーション総括.md(v1.0)で優先度A(最優先)とされた見積書・請求書の作成機能を主対象とし、見積書・請求書の作成・PDF保存、見積書から請求書への変換、入金ステータス管理、自社情報・振込先の設定、源泉徴収税額の計算を追加した(完了。イテレーション総括.md v2.0参照)。あわせて、イテレーション0からの残課題のうち★R1(起動エラー画面の復元導線)・★D3(取引先フリガナ・五十音順表示)・SEC-07(不要同梱物の整理)・★D1(アプリアイコン制作)に対応した。

イテレーション2では、日々の入金・経費を記録し、勘定科目での区分、領収書の添付、月別・年別の集計、確定申告・会計ソフト取り込み用のCSV出力ができるようにする。請求書を「入金済み」にしたときは、入金記録が自動で作成されるようにする。あわせて、イテレーション1で出た運用上の課題として、利用停止にした取引先を「利用中」へ戻せるようにする(★N1)ことと、下書きの見積書・請求書を確認のうえ完全に削除できるようにする(★N2)ことに対応する(プロジェクト計画書 3.3章)。

## 4. 用語集(クライアント目線)

| 用語 | 説明 |
|---|---|
| 事務HUB | 本プロジェクトで構築するデスクトップアプリケーションの正式名称 |
| アプリ基盤 | 事務HUBの土台となる、デスクトップアプリとしての骨格・データ保存の仕組み・バックアップ/復元機能をまとめた呼び方 |
| 取引先管理 | 取引先の情報を登録・確認・修正・整理する機能 |
| 取引先マスタ(台帳) | 登録済みの取引先情報のまとまり。以降の案件管理・見積請求・入出金経費・タスク管理などの機能から、名称等を重複登録せずに参照される共通の情報源となる(プロジェクト計画書 5.3章) |
| 手動エクスポート | 利用者が任意のタイミングで実行する、アプリ内データのファイル書き出し(バックアップ)操作 |
| 復元 | エクスポートしたファイルから、アプリ内データを元に戻す操作 |
| 利用停止 | 取引先を一覧から見えにくくしつつ、データ自体は削除せずに残しておく状態(10.1章 R-2参照) |
| 見積書 | 取引先へ金額等を提示するために作成する書類。作成後はPDFとして保存する |
| 請求書 | 取引先へ代金の支払いを求めるために作成する書類。見積書からの変換、または新規作成で作成できる。作成後はPDFとして保存する |
| 適格請求書等保存方式(インボイス制度) | 依頼者ご自身がインボイス登録番号を設定している場合に、見積書・請求書へ登録番号等の記載事項を表示する方式 |
| 区分記載請求書等 | 依頼者ご自身がインボイス登録番号を設定していない場合に、見積書・請求書へ表示する記載方式 |
| 源泉徴収税額 | 報酬を支払う側が、支払額からあらかじめ差し引いて納付する所得税額。請求書の明細行ごとに計算するかどうかを指定できる |
| 入金ステータス | 請求書ごとに管理する、代金が未収か入金済みかを示す状態 |
| 簡易登録 | 見積書・請求書の作成画面で、取引先マスタに未登録の相手を、名称等の最小限の情報でその場で登録する操作。結果として取引先マスタに正式な取引先として追加される |
| 入金記録 | 入ってきたお金を記録したもの。請求書を「入金済み」にしたときに自動で作成されるほか、利用者が直接入力して作成することもできる |
| 経費記録 | 事業のために支払ったお金を記録したもの。勘定科目を付け、領収書を添付できる |
| 勘定科目 | 入金・経費の内容を区分するための分類名(例: 通信費、消耗品費、売上高)。確定申告等での集計に用いる |
| 取消(入金記録) | 請求書の「入金済み」を取り消したときに、連動する入金記録を削除せず「取消済」の印を付けて残すこと。集計には含めず、履歴として残る |
| 履歴 | 入出金・経費の記録を変更・削除・取消した内容(いつ、何が、どう変わったか)を残しておく情報 |
| 領収書 | 経費の支払いを証明する書類。PDFまたは画像のファイルとして記録に添付する |
| 改変検知 | 保存した記録や領収書ファイルが、あとから書き換えられていないかを確認できる仕組み(電子帳簿保存法への配慮) |
| 下書き | PDF保存前の見積書・請求書。PDF保存済みの書類とは異なり、削除できる |

#### 他機能との連携範囲(今回確定分)

- 取引先管理: 見積書・請求書は、既存の取引先マスタから選択して作成する。未登録の相手へは、作成画面での簡易登録(10.2章 R-5)により対応する。入金記録は取引先と紐づけ、経費は任意で取引先(仕入先等)を紐づけられる。★N1により、利用停止の取引先を「利用中」へ戻せる(プロジェクト計画書 5.1章)
- 見積書・請求書: 入金記録は請求書と紐づける(請求書の「入金済み」操作から自動作成。F-21)。★N2により、下書きの削除を追加する(PDF保存済みは削除不可を維持)(プロジェクト計画書 5.1章)
- 入出金・経費: イテレーション1では入金ステータスは請求書側の独立項目としていたが、今回、入金済みへの変更と入金記録の作成を連動させる(F-15・F-21)
- 案件管理: 入出金・経費、見積書・請求書とも、案件との紐づけは今回持たない(プロジェクト計画書 5.1章)
- 電子帳簿保存法対応: 見積書・請求書(イテレーション1実装済み)に加え、入出金・経費の記録と領収書ファイルへ拡張する(プロジェクト計画書 5.1章)

## 6. 機能要件(フェーズ1)

### 6.1 アプリ基盤

#### F-01 アプリ起動・基本画面

- 入力: アプリの起動操作
- 処理: ローカルに保存されたデータを読み込み、取引先管理を含む各機能への入り口となる画面を表示する。以降のイテレーションで追加される案件管理・見積請求・入出金経費・タスク管理等の機能を、画面構成やデータ構造を大きく作り直すことなく追加できるようにしておく
- 出力: 事務HUBのトップ画面(各機能への導線)

#### F-02 データエクスポート(手動バックアップ)

- 入力: 利用者による「エクスポート」実行操作、保存先の指定
- 処理: 実行時点のアプリ内データ(取引先情報等)一式を1つのエクスポートファイルとして書き出す。自動実行するバックアップ機能は設けない
- 出力: エクスポートファイル(具体的な形式は設計フェーズで確定)

#### F-03 データ復元

- 入力: 利用者が指定するエクスポートファイル
- 処理: 指定されたエクスポートファイルの内容を読み込み、アプリ内のデータへ反映する。復元前データの扱い(上書き等)や、過去バージョンのエクスポートファイルとの互換性は設計フェーズで確定する
- 出力: 復元後のアプリ内データ、復元結果の画面表示

#### F-09 起動エラー画面からのデータ復元(★R1)

- 入力: データベース破損等によりアプリの起動に失敗した際の、起動エラー画面上での復元操作、利用者が指定するエクスポートファイル
- 処理: 起動エラー画面に、エクスポートファイルを選択して復元する導線を追加する。復元処理自体はF-03(データ復元)と同じ処理を用いる(10.2章 R-15にて確定)
- 出力: 復元後のアプリ内データ、復元結果の画面表示(起動エラー画面からの遷移を含む)

### 6.2 取引先管理

管理項目は下記のとおり確定した(10.1章 R-1、10.2章 R-16参照)。

**取引先の管理項目**

| 項目 | 内容 |
|---|---|
| 取引先ID | 他機能から参照するための一意の識別子(自動採番。利用者は直接入力しない) |
| 取引先名称 | 必須 |
| フリガナ | 任意(一覧の五十音順表示に用いる。10.2章 R-16にて確定) |
| 敬称 | 御中・様・(なし)等から選択(任意) |
| 担当者名 | 任意 |
| 郵便番号・住所 | 任意 |
| 電話番号 | 任意 |
| メールアドレス | 任意 |
| 取引先のインボイス登録番号 | 任意(見積書・請求書への記載を見据えた項目。プロジェクト計画書 5.3章) |
| メモ | 任意・自由記述 |
| 状態(利用中/利用停止) | システム管理項目(10.1章 R-2参照) |
| 登録日時・更新日時 | システム管理項目 |

#### F-04 取引先の登録

- 入力: 取引先名称・フリガナ・敬称・担当者名・住所・電話番号・メールアドレス・インボイス登録番号・メモ等(上記6.2章の管理項目)
- 処理: 入力内容を取引先マスタへ新規登録し、他機能から参照可能な一意の識別子(取引先ID)を自動付与する。必須項目が未入力の場合は登録できないようにする
- 出力: 登録された取引先情報、一覧画面への反映

#### F-05 取引先の一覧表示

- 入力: (任意)検索キーワード、並べ替え条件
- 処理: 登録済み取引先を一覧表示する。名称等でのキーワード検索、名称・登録日等での並べ替えができるようにする(登録件数の目安は〜50件程度。10.1章 R-3参照)。初期並び順はフリガナの五十音順とし、フリガナが未入力の取引先は一覧の末尾にまとめて表示する(10.2章 R-16にて確定。★D3解消)。「利用停止」とした取引先は非表示または区別可能な表示とする(10.1章 R-2参照)
- 出力: 取引先一覧画面

#### F-06 取引先の参照(詳細表示)

- 入力: 一覧からの選択操作
- 処理: 選択された取引先の詳細情報を表示する
- 出力: 取引先詳細画面

#### F-07 取引先の更新

- 入力: 修正後の取引先情報
- 処理: 指定された取引先の情報を更新する。更新後も取引先ID(識別子)は変わらず、他機能からの参照が維持されるようにする
- 出力: 更新後の取引先情報

#### F-08 取引先の削除(利用停止)

- 入力: 削除(利用停止)操作の対象取引先
- 処理: 対象取引先を「利用停止」状態にする(10.1章 R-2にて確定。データは削除せず保持し、完全削除の機能は設けない)。利用停止にした取引先は、F-25(★N1)により「利用中」へ戻すことができる。他機能から参照されている取引先の扱い(参照先での挙動)は、当該機能を扱うイテレーションで確定する(プロジェクト計画書 5.3章)
- 出力: 一覧・詳細画面上の状態変化(利用停止であることが分かる表示)

### 6.3 見積書・請求書関連(イテレーション1で新規追加)

#### F-10 自社情報・振込先の設定

- 入力: 氏名・屋号、住所、インボイス登録番号、振込先(銀行名・支店名・口座種別・口座番号・口座名義)(10.2章 R-12にて確定。電話番号・メールアドレス・印影画像は今回対象外)
- 処理: 入力内容を保存し、見積書・請求書のPDFに反映する。インボイス登録番号の入力有無により、適格請求書等保存方式/区分記載請求書等の記載形式を自動切替する(プロジェクト概要.md 5章)
- 出力: 保存された自社情報・振込先情報、見積書・請求書PDFへの反映

#### F-11 取引先の簡易登録(見積書・請求書作成時)

- 入力: 見積書・請求書の作成画面で入力する、未登録の相手の名称等の最小限の情報
- 処理: 取引先マスタに未登録の相手へ発行する場合、作成画面上でその場で取引先マスタへ簡易登録し、以降の見積書・請求書作成に利用する。結果として取引先マスタに正式な取引先として追加される。簡易登録時点では名称等の最小項目のみでよく、他の項目(6.2章参照)は後から取引先管理画面で補完できる(10.2章 R-5にて確定。★10解消)
- 出力: 簡易登録された取引先情報(取引先マスタ・一覧への反映)、作成画面での選択状態

#### F-12 見積書の作成・PDF保存

- 入力: 取引先(取引先マスタから選択、またはF-11で簡易登録)、見積書番号(自動採番)、発行日、有効期限(任意)、明細行(品名・数量・単位・単価・税率・金額)、自社情報・振込先(F-10)
- 処理:
  - 見積書番号を自動採番する(年+連番等の形式。手動編集は不可。10.2章 R-6にて確定)
  - 明細行ごとに標準税率10%・軽減税率8%を選択できるようにする(10.2章 R-7にて確定)
  - 有効期限は任意入力項目とする(10.2章 R-9にて確定)
  - 自社のインボイス登録番号(F-10)の入力有無により、適格請求書等保存方式/区分記載請求書等の記載形式を自動切替する
  - PDFとして保存する(印刷機能はアプリ側に設けない)
  - PDF保存後は内容を編集不可とし、修正が必要な場合は新しい見積書として再作成する(10.2章 R-14にて確定。電子帳簿保存法対応)
- 出力: 見積書PDFファイル、保存された見積書データ

#### F-13 見積書から請求書への変換

- 入力: 変換元の見積書、変換操作(ボタン一つ)
- 処理: 見積書の内容(取引先・明細行等)を引き継いだ請求書を作成する。変換後の請求書には、元の見積書への参照を保持し、画面上で行き来できるようにする(10.2章 R-13にて確定)
- 出力: 変換後の請求書(編集・PDF保存前の状態)

#### F-14 請求書の作成・PDF保存

- 入力: 取引先、請求書番号(自動採番)、発行日、支払期限(任意)、明細行、自社情報・振込先、源泉徴収要否(明細行ごと)
- 処理: F-12に準ずる(番号自動採番、税率選択、記載形式の自動切替、PDF保存後は編集不可)。支払期限は任意入力項目とする(10.2章 R-9)。源泉徴収税額を計算する場合はF-16の計算結果を反映する。見積書からの変換(F-13)によらず、新規に直接作成することもできる
- 出力: 請求書PDFファイル、保存された請求書データ

#### F-15 請求書の入金ステータス管理

- 入力: 対象請求書、入金ステータスの変更操作(未収→入金済み、および入金済みの取消)、入金日
- 処理: 利用者の手動操作により入金ステータスを未収/入金済みに切り替える。入金済みへの変更時には入金日をあわせて記録する(10.2章 R-10にて確定)。【イテレーション2で変更】入金済みへの変更・取消に連動して、入金記録の自動作成・「取消済」表示を行う(F-21。プロジェクト計画書 5.1章)
- 出力: 更新された入金ステータス・入金日、請求書一覧・詳細画面への反映

#### F-16 源泉徴収税額の計算

- 入力: 対象の明細行、源泉徴収の要否指定(明細行ごと)、支払金額
- 処理: 源泉徴収の対象として指定された明細行について、支払金額のうち100万円以下の部分は10.21%、100万円を超える部分は20.42%で計算する段階計算を行う(10.2章 R-11にて確定)
- 出力: 計算された源泉徴収税額、請求書への反映(源泉徴収税額を差し引いた請求金額の表示)

### 6.4 入出金・経費関連(イテレーション2で新規追加)

**入金・経費の記録の項目**(10.2章 R-24にて確定)

| 項目 | 必須/任意 | 内容 |
|---|---|---|
| 日付 | 必須 | 入金日または支払日 |
| 種別 | 必須 | 入金/経費のいずれか |
| 金額 | 必須 | 税込金額で入力する。消費税額は税区分から算出する(10.2章 R-32) |
| 勘定科目 | 必須 | F-17で管理する科目から選択(入金には収入の科目、経費には経費の科目) |
| 摘要・メモ | 必須 | 内容の説明(自由記述) |
| 取引先 | 任意 | 取引先マスタから選択。入金記録は請求書との連動分で取引先を引き継ぐ |
| 支払方法 | 任意 | 現金・振込・クレジットカード・その他から選択(固定。10.2章 R-32) |
| 税区分 | 任意 | 10%・8%(軽減)・非課税・対象外から選択(固定。10.2章 R-32) |
| 源泉徴収税額 | 自動 | 請求書から自動作成された入金記録のみ、源泉徴収税額を併記する(10.2章 R-28) |
| 領収書 | 任意 | PDF・画像を複数添付可(F-22) |
| 請求書 | 自動 | 請求書の「入金済み」から作成された入金記録のみ、元の請求書と紐づく |
| 状態 | システム管理 | 有効/取消済(入金記録のみ取消あり) |

インボイス登録有無の項目は設けない(10.2章 R-24)。

#### F-17 勘定科目の設定

- 入力: 勘定科目の名称、区分(経費/収入)、追加・名称変更・利用停止の操作
- 処理: 次の初期科目をあらかじめ登録する(10.2章 R-17にて確定)。
  - 経費(12科目): 通信費、旅費交通費、消耗品費、接待交際費、外注費、会議費、地代家賃、水道光熱費、広告宣伝費、租税公課、支払手数料、雑費
  - 収入(2科目): 売上高、雑収入
  - 利用者は科目を追加し、名称を変更できる。記録で一度でも利用した科目は削除できず、「利用停止」(新しい記録の選択肢に出さない状態)のみ可能とする
- 出力: 勘定科目の一覧、記録入力画面での選択肢

#### F-18 入金・経費の記録(入力・編集・削除)

- 入力: 6.4章の記録項目
- 処理: 入金と経費を記録できる。必須項目(日付・金額・勘定科目・摘要)が未入力の場合は登録できない。登録済みの記録は編集・削除ができ、編集・削除のたびにF-20の履歴を残す。削除は記録を完全に消さず、履歴に残る形(論理削除)で行う(10.2章 R-19)。入金記録は、請求書と連動して作成されるもの(F-21)のほか、利用者が直接入力して作成することもできる
- 出力: 登録・更新された記録、一覧への反映

#### F-19 入金・経費の一覧・検索

- 入力: (任意)検索条件
- 処理: 記録を一覧表示する。一覧には日付・種別・取引先・金額・勘定科目・摘要/メモ・領収書添付の有無・請求書番号(請求書から自動作成された入金記録のみ)を表示する(10.2章 R-21にて確定)。検索条件は日付範囲、金額範囲、取引先、勘定科目、種別(入金/経費)とする(10.2章 R-20にて確定。キーワード検索、領収書の有無での検索は設けない)。日付・金額・取引先での検索は電子帳簿保存法の検索要件に対応する。取消済の入金記録も、「取消済」と分かる表示で一覧に残す。削除した記録は一覧に出さず、履歴でのみ確認できる(10.2章 R-30)
- 出力: 記録一覧画面(検索結果を反映したもの)

#### F-20 記録の履歴

- 入力: 記録の変更・削除・取消の操作
- 処理: 変更日時、変更前後の値(項目ごと)、変更理由(任意入力)、削除・取消をした事実のすべてを履歴として残す(10.2章 R-19にて確定)。利用者は記録ごとに履歴を確認できる。履歴は利用者が編集・削除できない
- 出力: 記録ごとの履歴表示

#### F-21 請求書「入金済み」からの入金記録の自動作成・取消

- 入力: 請求書の「入金済み」への変更操作(F-15)、「入金済み」の取消操作
- 処理:
  - 請求書を「入金済み」にしたとき、金額・取引先・入金日を引き継いで入金記録を自動作成する。入金日は後から修正できる(プロジェクト計画書 5.1章)
  - 「入金済み」を取り消したときは、連動する入金記録を削除せず「取消済」の印を付けて残す。取消済の入金記録は集計から除外し、CSVには「取消済」の区分付きで出力する(10.2章 R-18にて確定)
  - 一部入金・分割入金は扱わない。請求書1件につき全額入金のみとする。ただし将来の拡張(分割入金等)を妨げないデータの持ち方を設計で考慮する(10.2章 R-22)
  - 自動作成する入金額は、源泉徴収後の実入金額とし、源泉徴収税額を記録に併記する。入金記録の勘定科目の初期値は「売上高」とする(10.2章 R-28)
  - 入金記録の入金日を修正しても、請求書側の入金日には反映しない(10.2章 R-28)
  - 取消後に再度「入金済み」にした場合は、取消済の記録は残し、新しい入金記録を作成する(10.2章 R-29)
  - 自動作成された入金記録は直接削除できず、請求書側での「入金済み」取消によってのみ取消となる(10.2章 R-30)
- 出力: 自動作成された入金記録、「取消済」表示の入金記録

#### F-22 領収書の添付と改変検知

- 入力: 記録に添付する領収書ファイル(PDF・画像、1件の記録に複数可)
- 処理: 記録に領収書ファイルを添付でき、添付した領収書は改変検知の対象とする。あとから書き換えられた場合に検知できるようにする(プロジェクト計画書 5.1章、プロジェクト概要.md 5章)。ファイルの形式・件数・容量の上限、改変検知の具体的な方式は設計フェーズで確定する(10.4章 ★16)。入出金・経費の記録そのものも改変検知の対象とする
- 出力: 記録に紐づく領収書の一覧・確認、改変を検知した場合の表示

#### F-23 集計

- 入力: 集計の期間(月・年)
- 処理: 月別・年別の入金合計・経費合計・差額(入金-経費)、および勘定科目別の経費合計を表示する(10.2章 R-25。計画書で確定済み)。取消済の入金記録、削除した記録は集計に含めない。取引先別の集計は設けない(5.2章)。年別集計は暦年(1月〜12月)とし、集計の基準日は記録の日付(入金日・支払日)とする(10.2章 R-31)
- 出力: 集計画面

#### F-24 CSV出力

- 入力: 期間(年・月)の指定
- 処理: 指定期間の入金・経費を1つのCSVに出力する(確定申告・会計ソフト取り込み用)。種別・勘定科目等での絞り込みは行わない(10.2章 R-23)。出力項目は次のとおり確定した。
  - 日付、種別、取引先、金額、勘定科目、摘要
  - 税区分、消費税額
  - 領収書ファイル名、請求書番号
  - 記録の状態(有効/取消済)
  - 登録・更新日時は含めない
  - 期間指定の基準日は記録の日付(入金日・支払日)とする(10.2章 R-31)。削除した記録は出力しない(10.2章 R-30)。消費税額は税区分から算出する(10.2章 R-32)
  - CSVの形式・文字コード・消費税額の端数処理は設計で確定する(10.4章 ★16)
- 出力: CSVファイル

#### F-25 取引先の「利用中」への復帰(★N1)

- 入力: 利用停止の取引先に対する「利用中に戻す」操作(取引先の一覧・詳細のどちらからも可)
- 処理: 利用停止の取引先を「利用中」へ戻す前に、軽い確認ダイアログを表示する(10.2章 R-26にて確定)。確定後は、戻した時点で、見積書・請求書の取引先選択肢へただちに復帰させる。取引先IDや登録内容は変わらない
- 出力: 「利用中」へ変わった取引先、一覧・詳細画面への反映

#### F-26 下書きの見積書・請求書の削除(★N2)

- 入力: 下書き(PDF保存前)の見積書・請求書に対する削除操作(一覧・詳細のどちらからも可)
- 処理: 確認画面を表示したうえで、完全に削除する。削除したものは復元できない(ゴミ箱機能は設けない)。PDF保存済みの見積書・請求書は削除できない(電子帳簿保存法対応のため従来の方針を維持)。下書きには書類番号が付かないため、番号の扱いは論点としない(10.2章 R-27にて確定)
- 出力: 削除後の一覧画面

## 7. 非機能要件

- 動作環境: インターネットに公開せず、ローカル環境のみで動作すること(プロジェクト計画書 6章)
- データ保存: アプリ内データはローカルに永続化され、アプリを再起動してもデータが失われないこと
- バックアップ・復元: 手動エクスポートと、そのファイルからの復元ができること。自動バックアップは設けない(6.1章)。起動エラー画面からも復元操作ができること(6.1章F-09)
- データ消失対策: 手動エクスポートおよび復元の操作を分かりやすくする。アプリ内で定期的な実施を促す案内表示は設けない(10.1章 R-4にて確定)。エクスポートファイルの保管先をPC本体とは別の媒体とすることの推奨は、操作マニュアルへの記載にとどめる
- セキュリティ: 認証機能は設けず、PC自体のログイン・画面ロックによる保護を前提とする。エクスポートファイル・見積書請求書PDFがPC外へ持ち出される可能性を踏まえ、取り扱いについては設計・セキュリティフェーズで確認する(プロジェクト計画書 7章)
- 法令配慮:
  - インボイス制度: 登録・未登録の両方に対応し、設定画面の登録番号入力の有無で見積書・請求書の表示内容を自動切替する(プロジェクト概要.md 5章)
  - 電子帳簿保存法: 発行した見積書・請求書を改変せず保存し、日付・金額・取引先の各条件で検索できるようにする(プロジェクト概要.md 5章)。改変防止のため、PDF保存後の見積書・請求書は編集不可とし、修正時は新しい書類として再作成する(10.2章 R-14)。具体的な保存形式・検索方式は設計フェーズで確定する(10.3章 ★12)
  - 【イテレーション2で追加】電子帳簿保存法の対応水準(改変検知、日付・金額・取引先での検索)を、入出金・経費の記録と領収書ファイルにも適用する(F-19・F-22)。記録の編集・削除は可能とし、変更・削除・取消の履歴を残す(F-20)。保存方式・検索方式は設計フェーズで確定する(10.4章 ★16)
- データ保護(イテレーション2追加): 領収書ファイルの添付によるデータ量の増加と、エクスポート・復元の対象に入出金・経費・領収書が含まれるかは、設計フェーズで確認する(10.4章 ★16)
- 拡張性: 取引先マスタは、以降の機能(案件・見積請求・入出金経費・タスク)から重複登録なく参照できるデータ構造とする(プロジェクト計画書 5.3章)
- 利用のしやすさ: 依頼者ご本人が一人で日常的に使う想定のため、専門知識がなくても迷わず操作できる分かりやすい画面・案内文言とする

## 8. 制約条件

- 予算: 特に定めなし(プロジェクト計画書 6章に記載なし)
- 納期: 特に期限を設けず、順次進める(プロジェクト計画書 4.3章・6章)
- 体制: 特に定めなし(プロジェクト計画書 6章に記載なし)
- 技術選定(使用言語・フレームワーク・データベース等): イテレーション0で確定済み(Mac専用、Electron+TypeScript+React等。基本設計書.md参照)の技術選定を踏襲する。PDF出力等、見積書・請求書機能で新たに必要となる技術要素の選定は、設計フェーズ(architecture)にて確定する(プロジェクト計画書 6章)。イテレーション2も既存の保存方式・DB構成を踏襲し、領収書ファイルの保存方式、CSVの形式・文字コード等は設計フェーズで確定する(プロジェクト計画書 4.2章)

## 9. 前提条件

- 利用者: 依頼者ご本人のみ(複数ユーザーでの利用は想定しない)(プロジェクト計画書 6章)
- 利用端末: PCを中心とする(プロジェクト計画書 6章)

- 利用するPCのOS: Mac専用で確定(旧★5解消。基本設計書.md 2章・8.1章★B1参照)
