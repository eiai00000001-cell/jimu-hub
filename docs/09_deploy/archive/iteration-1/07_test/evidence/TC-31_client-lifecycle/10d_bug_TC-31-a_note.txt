【不具合TC-31-a】F-08 利用停止後、同一の詳細画面内でバッジ・編集ボタンが更新されない

再現手順:
1. 取引先を1件新規登録する
2. 一覧からその取引先の詳細画面を開く
3. 「利用停止にする」→確認ダイアログで「はい」を押す
4. 完了メッセージ「取引先を利用停止にしました」は表示されるが、
   同じ詳細画面内のバッジ(状態欄・見出し横とも)は「利用中」のまま、
   「編集」ボタンも活性のままで、「利用停止にする」ボタンも消えない

期待結果(詳細設計書4.8章手順4):
「一覧・詳細画面の表示を最新化し、状態バッジを反映する」

実際の結果:
同一詳細画面インスタンス内では、Main側のデータ更新(status=inactiveへのUPDATE)自体は
正しく行われている(window.jimuhubApi.getClient(id)で直接確認し、statusが'inactive'に
なっていることを確認済み)が、画面(ClientDetailPage)側は再取得(再フェッチ)されないため
表示が古いまま取り残される。

原因(コード参照のみ・修正はdeveloper対応):
- src/renderer/src/pages/ClientDetailPage.tsx の useEffect の依存配列が [clientId] のみであり、
  利用停止操作後も clientId 自体は変わらないため再フェッチのトリガーにならない。
- src/renderer/src/App.tsx の onDeactivated は同じ id で route を更新するのみで、
  ClientDetailPage は key={route.id} のため再マウントされない。

再現しない操作(回避策の確認):
「一覧へ戻る」→一覧から同じ取引先を再度開く、またはホームへ戻ってから
取引先管理を開き直す、等いったん画面を離れて戻ると、一覧・詳細とも正しい状態
(利用停止バッジ・グレー表示)が表示されることを確認済み(スクリーンショット08・09参照)。

重大度: 中(データ自体は正しく更新されており、画面遷移をやり直せば正しい表示に戻るため
実害は限定的だが、詳細設計書の明示手順に反しており、利用者が同一画面内で
一時的に誤った状態を見てしまう)
