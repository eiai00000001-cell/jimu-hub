## F-01 アプリ起動・基本画面

### TC-01

- 機能ID: F-01 / 観点: ①機能テスト
- テスト内容: 正常起動時のトップ画面表示
- 事前条件: テスト専用データディレクトリが空の状態
- 手順:
  1. アプリを起動する
  2. トップ画面の表示内容を確認する
- 期待結果: トップ画面に「取引先登録件数(利用中)」が0件と表示され、サイドバーに「ホーム」「取引先管理」「案件管理」「見積書・請求書」「入出金・経費」「タスク・期限」が表示される(v4.1改訂: 旧版は「準備中」メニューの表示と記載)。タイトルバーが「事務HUB - ホーム」と表示される(詳細設計書4.1章、デザインガイド5.2章)

### TC-02

- 機能ID: F-01 / 観点: ②異常系
- テスト内容: データベースファイル破損時の起動エラー画面表示
- 事前条件: データ保存先ディレクトリに、有効なSQLiteファイルではない内容の`data.sqlite`を事前配置しておく
- 手順:
  1. 上記の状態でアプリを起動する
  2. 表示内容を確認する
- 期待結果: 起動エラー画面に「データを読み込めませんでした。ファイルが破損している可能性があります。エクスポートファイルからの復元をお試しください」と表示される(詳細設計書4.1章手順5・8章)

### TC-03

- 機能ID: F-01 / 観点: ⑤結合確認
- テスト内容: サイドバーのメニューの挙動(全画面共通)。イテレーション4で「準備中」のメニューはなくなった
- 事前条件: アプリが正常起動していること
- 手順:
  1. トップ画面で、サイドバーの「取引先管理」「見積書・請求書」「入出金・経費」「案件管理」「タスク・期限」を順に押す
  2. 取引先一覧画面から「タスク・期限」を押し、「ホーム」を押す
- 期待結果: すべてのメニューが画面遷移し(「事務HUB - 取引先一覧」「…見積書・請求書」「…入出金・経費」「…案件一覧」「…タスク一覧」「…ホーム」)、サイドバーの選択状態が遷移先になる。「以降のイテレーションで実装予定です」という案内や、無効表示のメニューは存在しない(詳細設計書3.0章・3.1章)
- v1.1改訂: 「見積書・請求書」が遷移する仕様へ改訂した。v4.1改訂(★H1): 「タスク・期限」の実装により、準備中のメニューがなくなったため、期待結果を「すべてのメニューが遷移する」へ改訂した(旧版は「準備中」の案内が出て遷移しないことを確認していた)

## F-03 データ復元

### TC-07

- 機能ID: F-03 / 観点: ③データ整合性
- テスト内容: 復元が「全置換」であること(マージではなく完全な置き換え)
- 事前条件: 取引先Aのみを含むエクスポートファイルを用意しておく
- 手順:
  1. 取引先Aを登録し、エクスポートする(ファイルにはAのみが含まれる)
  2. 取引先Bを追加登録する(この時点でDBにはA・Bの2件)
  3. 手順1で作成したファイル(Aのみ)で復元する
- 期待結果: 復元後は取引先Aのみが残り、Bは削除される(全件削除後に再INSERTする全置換方式であることを確認、詳細設計書4.3章手順6)

### TC-08

- 機能ID: F-03 / 観点: ①機能テスト・④回帰確認
- テスト内容: データ復元の2段階フロー(警告確認)
- 事前条件: アプリが正常起動していること
- 手順:
  1. 「データを復元」→「ファイルを選択して復元」を押す(確認状態へ遷移)
  2. 「キャンセル」を押す
  3. 再度「ファイルを選択して復元」→「続行」を押す
- 期待結果: 手順2ではOS標準ダイアログを開かず初期状態に戻る。手順3の「続行」押下時のみOS標準ファイル選択ダイアログが開く(詳細設計書3.7章、レビュー結果報告書v0.1 No.6で確認済みの内容の回帰確認)

### TC-09

- 機能ID: F-03 / 観点: ②異常系
- テスト内容: 壊れたJSONファイルの復元
- 事前条件: 内容が不正なJSON(パース不能)のファイルを用意しておく
- 手順:
  1. 上記ファイルを選択して復元を実行する
- 期待結果: 「選択されたファイルを読み込めませんでした。正しいエクスポートファイルかご確認ください」と表示される(詳細設計書4.3章手順3・8章)

### TC-10

- 機能ID: F-03 / 観点: ②異常系
- テスト内容: schemaVersionが対応範囲より新しいファイルの復元
- 事前条件: `schemaVersion`に999等、現行より大きい値を設定したファイルを用意しておく

- 期待結果: 「このファイルは新しいバージョンの事務HUBで作成されたため復元できません。アプリを更新してください」と表示される(詳細設計書4.3章手順4・8章)

### TC-11

- 機能ID: F-03 / 観点: ③データ整合性
- テスト内容: 退避コピーの世代管理(直近3世代のみ保持)
- 事前条件: 復元を4回連続で実行できる状態
- 手順:
  1. 同一の復元ファイルで、復元操作を4回連続で実行する
  2. 退避コピー保存先(`backups/`)のファイル数を確認する
- 期待結果: 4回実行しても、退避コピーは直近3世代のみ保持され、最も古い世代は自動削除される(詳細設計書4.3章手順5)

### TC-12

- 機能ID: F-03 / 観点: ③データ整合性
- テスト内容: 復元処理失敗時のロールバック・自動復旧
- 事前条件: `clients`テーブルのCHECK制約(`status`)に違反する値を含む復元ファイルを用意しておく。事前に別の取引先を1件登録しておく
- 手順:
  1. 上記ファイルで復元を実行する(トランザクション失敗を狙う)
  2. 表示内容を確認する
  3. 復元前に登録していた取引先データが残っているか確認する
  4. 続けて新規登録操作を行い、アプリが継続して動作するか確認する
- 期待結果: 「復元に失敗しました。データは復元前の状態に戻しました」と表示され、事前に登録していたデータは失われず、その後も通常どおり読み書きが継続できる(詳細設計書4.3章手順8)
