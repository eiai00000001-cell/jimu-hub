## 1. 文書情報

- 作成日: 2026-09-26
- 版数: v1.0

## 2. 対象範囲

要件定義書 5.1章のフェーズ1スコープに基づき、以下を対象とする。

- アプリ基盤(アプリ起動・基本画面、手動エクスポート、データ復元)
- 取引先管理(登録・一覧表示・参照・更新・削除)

案件管理・見積請求・入出金経費・タスク管理、取引先を参照する各機能側の連携実装等は対象外とする(要件定義書 5.2章)。

## 4. 機能別詳細仕様

### F-01 アプリ起動・基本画面

#### 目的

ローカル環境で事務HUBを起動し、以降の各機能(取引先管理、および将来追加される案件管理等)へアクセスできる状態にする(要件定義書 6.1章)。

#### 入力

- アプリの起動操作

#### 処理内容

- ローカルに保存されているデータを読み込む(具体的な保存形式・保存場所は設計フェーズで確定。要件定義書 8章)
- 取引先管理を含む各機能への入り口となるトップ画面を表示する
- 画面構成・データ構造は、以降のイテレーションで追加される案件管理・見積請求・入出金経費・タスク管理等の機能を、大きな作り直しなく追加できることを考慮したものとする(要件定義書 7章)

#### 出力

- 事務HUBのトップ画面(各機能への導線)

#### 例外・エラー時の扱い

- 保存データの読み込みに失敗した場合の挙動(エラー表示・復旧手段等)は、設計フェーズで具体化する

---

### F-02 データエクスポート(手動バックアップ)

#### 目的

利用者の意思で任意のタイミングでアプリ内データをファイルに書き出し、データ消失に備える(要件定義書 6.1章)。

#### 入力

- 利用者による「エクスポート」実行操作
- 保存先の指定

#### 処理内容

- 実行時点のアプリ内データ(取引先情報等)一式を1つのエクスポートファイルとして書き出す
- 自動実行するバックアップ機能は設けない(要件定義書 5.2章)
- アプリ内で定期的な実施を促す案内表示は設けない(要件定義書 10.1章 R-4にて確定)。エクスポートファイルの保管先をPC本体とは別の媒体とすることの推奨は、操作マニュアルへの記載にとどめる

#### 出力

- エクスポートファイル(具体的なファイル形式は設計フェーズで確定)

#### 例外・エラー時の扱い

- 保存先への書き込みに失敗した場合(空き容量不足、アクセス権限なし等)のエラー表示・再試行手段は、設計フェーズで具体化する

---

### F-03 データ復元

#### 目的

エクスポートファイルから、アプリ内のデータを復元できるようにする(要件定義書 6.1章)。

#### 入力

- 利用者が指定するエクスポートファイル

#### 処理内容

- 指定されたエクスポートファイルの内容を読み込み、アプリ内のデータへ反映する
- 復元前データの扱い(上書きするか、合成するか等)は、設計フェーズで確定する
- 過去バージョンのエクスポートファイルとの互換性(データ構造が変わった場合の扱い)は、設計フェーズで考慮する(プロジェクト計画書 7章)

#### 出力

- 復元後のアプリ内データ
- 復元結果を示す画面表示(成功・失敗の別)

#### 例外・エラー時の扱い

- 指定ファイルが破損している場合、形式が異なる場合、バージョンが古い場合等の扱いは、設計フェーズで具体化する

---

### F-04 取引先の登録

#### 目的

新しい取引先の情報をアプリに登録できるようにする(要件定義書 6.2章)。

#### 入力

- 取引先名称、敬称、担当者名、郵便番号・住所、電話番号、メールアドレス、取引先のインボイス登録番号、メモ(項目の詳細は5章データ項目定義を参照)

#### 処理内容

- 入力内容を取引先マスタへ新規登録する
- 他機能から参照可能な一意の識別子(取引先ID)を自動採番する
- 必須項目(取引先名称)が未入力の場合は登録できないようにする

#### 出力

- 登録された取引先情報
- 取引先一覧画面への反映

#### 例外・エラー時の扱い

- 必須項目未入力時は、登録を行わずエラーメッセージを表示する
- 入力形式の妥当性チェック(メールアドレスの形式等)の要否・詳細は設計フェーズで具体化する

---

### F-05 取引先の一覧表示

#### 目的

登録済みの取引先を一覧で確認できるようにする(要件定義書 6.2章)。

#### 入力

- (任意)検索キーワード
- (任意)並べ替え条件(名称・登録日等)

#### 処理内容

- 登録済み取引先を一覧表示する
- 名称等でのキーワード部分一致検索ができるようにする
- 名称・登録日等での並べ替えができるようにする
- 「利用停止」とした取引先は、非表示または区別可能な表示とする(F-08、要件定義書 10.1章 R-2参照)
- 登録件数の目安は〜50件程度である(要件定義書 10.1章 R-3にて確定)。検索・並べ替えの具体的な挙動(部分一致の範囲、並べ替え項目の詳細等)は設計フェーズで具体化する

#### 出力

- 取引先一覧画面(検索結果・並べ替え結果を反映したもの)

#### 例外・エラー時の扱い

- 該当する取引先が0件の場合の表示(空データ時の案内文言等)は、設計フェーズで具体化する

---

### F-06 取引先の参照(詳細表示)

#### 目的

特定の取引先の登録内容を確認できるようにする(要件定義書 6.2章)。

#### 入力

- 一覧からの選択操作

#### 処理内容

- 選択された取引先の詳細情報(5章データ項目定義の全項目)を表示する

#### 出力

- 取引先詳細画面

#### 例外・エラー時の扱い

- 選択対象の取引先が既に削除(利用停止)されている場合の表示方法は、設計フェーズで具体化する

---

### F-07 取引先の更新

#### 目的

登録済みの取引先情報を修正できるようにする(要件定義書 6.2章)。

#### 入力

- 修正後の取引先情報(項目は5章データ項目定義に準ずる)

#### 処理内容

- 指定された取引先の情報を更新する
- 更新後も取引先ID(識別子)は変わらず、他機能からの参照が維持されるようにする

#### 出力

- 更新後の取引先情報

#### 例外・エラー時の扱い

- 必須項目(取引先名称)を空欄にした場合は更新できないようにする(F-04に準ずる)

---

### F-08 取引先の削除(利用停止)

#### 目的

使わなくなった取引先を一覧から整理できるようにする(要件定義書 6.2章)。

#### 入力

- 削除(利用停止)操作の対象取引先

#### 処理内容

- 対象取引先を「利用停止」状態にする(要件定義書 10.1章 R-2にて確定。データは削除せず保持し、完全削除の機能は設けない)
- 他機能(案件管理・見積請求・入出金経費・タスク管理)から参照されている取引先を削除(利用停止)した場合の挙動は、当該機能を扱うイテレーションで確定する(プロジェクト計画書 5.3章)

#### 出力

- 一覧・詳細画面上の状態変化(利用停止であることが分かる表示)

#### 例外・エラー時の扱い

- 誤操作防止のための確認ダイアログ等の要否は、設計フェーズ・デザインフェーズで具体化する

## 5. データ項目定義

取引先マスタの管理項目(要件定義書 6.2章、10.1章 R-1にて確定)

| 項目名 | 必須/任意 | 形式(案) | 備考 |
|---|---|---|---|
| 取引先ID | システム管理項目 | 自動採番 | 他機能から参照するための一意の識別子。利用者は直接入力しない |
| 取引先名称 | 必須 | 文字列 | |
| 敬称 | 任意 | 選択式(御中・様・(なし)等) | 選択肢の詳細は設計フェーズで確定 |
| 担当者名 | 任意 | 文字列 | |
| 郵便番号・住所 | 任意 | 文字列 | |
| 電話番号 | 任意 | 文字列 | |
| メールアドレス | 任意 | 文字列 | 形式チェックの要否は設計フェーズで確定 |
| 取引先のインボイス登録番号 | 任意 | 文字列 | 見積書・請求書への記載を見据えた項目(プロジェクト計画書 5.3章) |
| メモ | 任意 | 自由記述(複数行) | |
| 状態(利用中/利用停止) | システム管理項目 | 区分値 | 要件定義書 10.1章 R-2参照 |
| 登録日時 | システム管理項目 | 日時 | |
| 更新日時 | システム管理項目 | 日時 | |
