## 2. プロジェクト概要

### 2.1 クライアント情報

- 依頼者: 個人事業主の方(ご本人が唯一の利用者)(プロジェクト計画書 2.1章)

### 2.2 プロジェクトタイプ

- ローカル環境のみで動作するデスクトップアプリケーション「事務HUB」の新規構築(プロジェクト計画書 6章)

## 3. 背景・目的

「事務HUB」は、個人事業主である依頼者ご本人が日々行う事務作業(見積書・請求書の作成、入出金・経費の記録、取引先・案件の管理、タスク・期限の管理)を一つのツールに集約し、効率的に管理できるようにすることを目的として開発する(プロジェクト計画書 2.2章・3.1章)。

イテレーション0では、以降の機能を載せていく土台となる「アプリ基盤」と、以降の各機能から参照される共通の台帳としての「取引先管理」を整備する(プロジェクト計画書 3.2章)。

## 4. 用語集(クライアント目線)

| 用語 | 説明 |
|---|---|
| 事務HUB | 本プロジェクトで構築するデスクトップアプリケーションの正式名称 |
| アプリ基盤 | 事務HUBの土台となる、デスクトップアプリとしての骨格・データ保存の仕組み・バックアップ/復元機能をまとめた呼び方 |
| 取引先管理 | 取引先の情報を登録・確認・修正・整理する機能 |
| 取引先マスタ(台帳) | 登録済みの取引先情報のまとまり。以降の案件管理・見積請求・入出金経費・タスク管理などの機能から、名称等を重複登録せずに参照される共通の情報源となる(プロジェクト計画書 5.3章) |
| 手動エクスポート | 利用者が任意のタイミングで実行する、アプリ内データのファイル書き出し(バックアップ)操作 |
| 復元 | エクスポートしたファイルから、アプリ内データを元に戻す操作 |
| 利用停止 | 取引先を一覧から見えにくくしつつ、データ自体は削除せずに残しておく状態(10章 R-2参照) |

## 5. スコープ

### 5.1 フェーズ1(今回対象)

- アプリ基盤
  - ローカル環境のみで動作するデスクトップアプリとしての骨格
  - データの保存方式(具体的な形式・場所は設計フェーズで確定)
  - 手動エクスポートによるバックアップ、エクスポートデータからの復元
  - 以降の機能(案件管理・見積請求・入出金経費・タスク管理)を追加していける画面・データの構成
- 取引先管理
  - 取引先情報の登録・一覧表示・参照・更新・削除(利用停止)
  - 取引先マスタとしての整備(以降の機能から参照される共通の台帳とする)

(プロジェクト計画書 5.1章に基づく)

### 5.2 フェーズ2以降(対象外)

- 案件管理、見積書・請求書の作成、入出金・経費の記録、タスク・期限管理(プロジェクト計画書 4.4章・5.2章)
- 取引先を参照する各機能側の連携実装(取引先詳細画面での関連案件・請求・入出金の一覧表示等を含む)(プロジェクト計画書 5.3章)
- 依頼者ご自身の事業者情報(屋号・インボイス登録番号等)の管理(プロジェクト計画書 5.3章)
- 認証(ログイン)機能、複数ユーザーでの利用、インターネット公開・クラウド同期、既存データの移行、自動バックアップ(プロジェクト計画書 5.2章)

なお、取引先管理と以降の機能との連携範囲の線引きは、プロジェクト計画書 5.3章の整理(ご了承済み)のとおりとする。

## 6. 機能要件(フェーズ1)

### 6.1 アプリ基盤

#### F-01 アプリ起動・基本画面

- 入力: アプリの起動操作
- 処理: ローカルに保存されたデータを読み込み、取引先管理を含む各機能への入り口となる画面を表示する。以降のイテレーションで追加される案件管理・見積請求・入出金経費・タスク管理等の機能を、画面構成やデータ構造を大きく作り直すことなく追加できるようにしておく
- 出力: 事務HUBのトップ画面(各機能への導線)

#### F-02 データエクスポート(手動バックアップ)

- 入力: 利用者による「エクスポート」実行操作、保存先の指定
- 処理: 実行時点のアプリ内データ(取引先情報等)一式を1つのエクスポートファイルとして書き出す。自動実行するバックアップ機能は設けない
- 出力: エクスポートファイル(具体的な形式は設計フェーズで確定)

#### F-03 データ復元

- 入力: 利用者が指定するエクスポートファイル
- 処理: 指定されたエクスポートファイルの内容を読み込み、アプリ内のデータへ反映する。復元前データの扱い(上書き等)や、過去バージョンのエクスポートファイルとの互換性は設計フェーズで確定する
- 出力: 復元後のアプリ内データ、復元結果の画面表示

### 6.2 取引先管理

管理項目は下記のとおり確定した(10章 R-1参照)。

**取引先の管理項目**

| 項目 | 内容 |
|---|---|
| 取引先ID | 他機能から参照するための一意の識別子(自動採番。利用者は直接入力しない) |
| 取引先名称 | 必須 |
| 敬称 | 御中・様・(なし)等から選択(任意) |
| 担当者名 | 任意 |
| 郵便番号・住所 | 任意 |
| 電話番号 | 任意 |
| メールアドレス | 任意 |
| 取引先のインボイス登録番号 | 任意(見積書・請求書への記載を見据えた項目。プロジェクト計画書 5.3章) |
| メモ | 任意・自由記述 |
| 状態(利用中/利用停止) | システム管理項目(10章 R-2参照) |
| 登録日時・更新日時 | システム管理項目 |

#### F-04 取引先の登録

- 入力: 取引先名称・敬称・担当者名・住所・電話番号・メールアドレス・インボイス登録番号・メモ等(上記6.2章の管理項目案)
- 処理: 入力内容を取引先マスタへ新規登録し、他機能から参照可能な一意の識別子(取引先ID)を自動付与する。必須項目が未入力の場合は登録できないようにする
- 出力: 登録された取引先情報、一覧画面への反映

#### F-05 取引先の一覧表示

- 入力: (任意)検索キーワード、並べ替え条件
- 処理: 登録済み取引先を一覧表示する。名称等でのキーワード検索、名称・登録日等での並べ替えができるようにする(登録件数の目安は〜50件程度。10章 R-3参照)。「利用停止」とした取引先は非表示または区別可能な表示とする(10章 R-2参照)
- 出力: 取引先一覧画面

#### F-06 取引先の参照(詳細表示)

- 入力: 一覧からの選択操作
- 処理: 選択された取引先の詳細情報を表示する
- 出力: 取引先詳細画面

#### F-07 取引先の更新

- 入力: 修正後の取引先情報
- 処理: 指定された取引先の情報を更新する。更新後も取引先ID(識別子)は変わらず、他機能からの参照が維持されるようにする
- 出力: 更新後の取引先情報

#### F-08 取引先の削除(利用停止)

- 入力: 削除(利用停止)操作の対象取引先
- 処理: 対象取引先を「利用停止」状態にする(10章 R-2にて確定。データは削除せず保持し、完全削除の機能は設けない)。他機能から参照されている取引先の扱い(参照先での挙動)は、当該機能を扱うイテレーションで確定する(プロジェクト計画書 5.3章)
- 出力: 一覧・詳細画面上の状態変化(利用停止であることが分かる表示)

## 7. 非機能要件

- 動作環境: インターネットに公開せず、ローカル環境のみで動作すること(プロジェクト計画書 6章)
- データ保存: アプリ内データはローカルに永続化され、アプリを再起動してもデータが失われないこと
- バックアップ・復元: 手動エクスポートと、そのファイルからの復元ができること。自動バックアップは設けない(6.1章)
- データ消失対策: 手動エクスポートおよび復元の操作を分かりやすくする。アプリ内で定期的な実施を促す案内表示は設けない(10章 R-4にて確定)。エクスポートファイルの保管先をPC本体とは別の媒体とすることの推奨は、操作マニュアルへの記載にとどめる
- セキュリティ: 認証機能は設けず、PC自体のログイン・画面ロックによる保護を前提とする。エクスポートファイルがPC外へ持ち出される可能性を踏まえ、取り扱いについては設計・セキュリティフェーズで確認する(プロジェクト計画書 7章)
- 法令配慮: インボイス制度・電子帳簿保存法に配慮した記録・保存ができる状態を見据えた設計とする(具体的な対応範囲は該当機能のイテレーションで確定。プロジェクト計画書 7章・8章 ★8)
- 拡張性: 取引先マスタは、以降の機能(案件・見積請求・入出金経費・タスク)から重複登録なく参照できるデータ構造とする(プロジェクト計画書 5.3章)
- 利用のしやすさ: 依頼者ご本人が一人で日常的に使う想定のため、専門知識がなくても迷わず操作できる分かりやすい画面・案内文言とする

- 体制: 特に定めなし(プロジェクト計画書 6章に記載なし)

## 9. 前提条件

- 利用者: 依頼者ご本人のみ(複数ユーザーでの利用は想定しない)(プロジェクト計画書 6章)
- 利用端末: PCを中心とする(プロジェクト計画書 6章)
- 認証: 設けない。PCのログイン・画面ロックで保護する(プロジェクト計画書 5.2章)
- 提供形態: ローカル環境のみで動作するデスクトップアプリ(プロジェクト計画書 6章)
- 既存データの移行: 発生しない(プロジェクト計画書 2.2章)
- 利用するPCのOS: 本フェーズでは未確定。設計フェーズ着手前に確認する(プロジェクト計画書 8章 ★5、本書10章に持ち越し)
- 取引先の登録件数の目安: 〜50件程度(10章 R-3にて確定)
